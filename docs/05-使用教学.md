## 一、程序是什么

CardForge 把「一句话设想」锻成「能上牌桌的卡」。一条流水线：

```
结构化规格 ──→ 卡文(PSCT) + Lua脚本 ──→ 卡图 + 卡面合成 ──→ 导出上桌
   │                    │                      │                  │
 G1 平衡审计      PSCT 校验器 39 条       本机 ComfyUI 出图    EDOPro expansions
 数值/合法性      G2 脚本静态检查         25 罕贵 × 6 出框     MDPro3 .ypk / .ydk
                 G3 实跑对局验证         直接导出卡面          一键安装(带备份)
```

### 两条贯穿全程序的设计铁律

1. **不做「自然语言 → Lua」直译。** 卡文与脚本都是同一份结构化「效果 IR」的
   确定性投影：`意图 → EffectSpec → PSCT 卡文 → Lua`。你在界面里填的是结构化
   效果（种类/时点/目标/代价），程序投影出规范卡文和可跑脚本——所以卡文与脚本
   永远一致，也不会出现「AI 幻觉出来的 API」。
2. **质量门全部是确定性代码，AI 绝不参与裁决。** 大模型（若配置）只处于「提议」
   位置（AI 起草卡文）；问题清单、门结论、计数全部由内核校验器产出。助手艾莉娅
   只把结论翻译成人话，从不替你判断。

### 两种使用形态

| 形态 | 适合 | 启动方式 |
|---|---|---|
| **源码树**（本项目目录） | 开发、二次开发、要全部能力 | 双击 `启动.bat`，或 `python -m cardforge launch` |
| **打包版** `dist/CardForge/` | 拷去别的 Windows 电脑直接用 | 拷整个文件夹，双击 `CardForge.exe`（无参 = launch） |

打包版把 Python 运行时、Pillow、字体、全部数据都装进 `_internal/`，目标电脑
**不需要装任何东西**（Windows x64 即可）。详见 §6.9 打包。

## 二、环境准备

### 2.1 四层能力模型：缺哪层降级到哪层，没有一层会阻断主流程

| 层 | 能力 | 需要什么 | 缺失时的降级 |
|---|---|---|---|
| **L0 必需** | 造卡、PSCT 卡文、Lua 生成、平衡审计、导出、界面 | Python 3.10+（打包版连这个都自带） | — |
| **L1 渲染** | 卡面 PNG 合成、25 罕贵、6 出框、打印级导出 | Pillow（打包版已内置） | 浏览器端矢量卡面预览仍可用 |
| **L2 出图** | 卡图生成、分层出图、系列一致性 | 本机 ComfyUI（`127.0.0.1:8188`）+ 出图模型 | 保留「上传自己的图」通路 |
| **L3 对局** | G3 实跑验证（真开一局对战） | ocgcore 原生库（`ocgcore.dll` 等） | 降级为静态 Lua 校验并**明确标注** |
| LLM 可选 | AI 起草卡文 | LM Studio / Ollama / 任意 OpenAI 兼容端点 | 按钮诚实降级，给配置入口 |

### 2.2 各可选环境怎么装

**L1（Pillow）**——源码树里 `pip install Pillow` 即可；打包版已内置。
渲染增强链（可选）：`numpy fonttools brotli svglib reportlab pymupdf`。

**L2（ComfyUI）**——本机跑一个 ComfyUI，默认端口 `8188`。CardForge 会自动探测
并读取你机器上**实际存在的模型**自适应参数。建议模型（许可见 §九）：

- `animagine`（Animagine XL 4.0）：可商用，优先选；
- `qwen_image`（Qwen-Image 2.1）：Apache-2.0，可商用；
- `krea2`：本机首选，商用需核对条款；
- ⚠ **pony / illustrious / noobai 禁止商业化**，选型前务必看 `art/profiles.py` 各档案 notes。

可选增强：`models/clip_vision/` 与 `models/controlnet/` 里有模型时，IPAdapter /
ControlNet 链路自动启用；为空则自动跳过（不报错）。

**L3（ocgcore 引擎）**——三选一：

1. 把 `ocgcore.dll`（Windows）放进 `vendor/engine/`；
2. 设环境变量 `CARDFORGE_OCGCORE=<完整路径>`；
3. 装了 EDOPro 的话不用管——doctor 会扫描候选位置（EDOPro 根目录自带这个库）。

没有引擎时 G3 诚实降级为静态校验，界面与 doctor 都会明说。

**LLM**——见 §6.4。

### 2.3 环境自检：`doctor`

```powershell
python -m cardforge doctor          # 人读版（逐项 ✓/✗ + 中文提示）
python -m cardforge doctor --json   # 机器可读（脚本/探针用）
```

自检清单（当前版本 12 项）逐项含义：

| 检查项 | ok=true 说明 | 不 ok 时 |
|---|---|---|
| 工作区 | `workspace/` 可读写（惰性建目录） | 检查磁盘权限/路径 |
| 内置数据 | `data/`（术语表/知识库/素材）完整 | 包不完整，重新获取 |
| 卡框素材 | 15 种官方卡框 87 张素材可用 | 渲染器回退程序化框体（warn） |
| 知识库 | PSCT/Lua API 快照完整 | 校验能力受限 |
| Pillow | L1 渲染可用 | 只有矢量预览 |
| 排版引擎 | 禁则/悬挂缩进/混排可用 | — |
| 字体 | 6 个字体角色全部解析（内置 asset-ttf 优先） | 中文可能出方框 |
| ComfyUI | 8188 在线 | L2 出图不可用（warn，不影响其他） |
| LLM 接入 | 已配模型 | 艾莉娅走规则通路，功能不缺失 |
| 对局引擎 | 找到 ocgcore | L3 降级静态校验（warn） |
| 官方卡池 | `cards_zh.cdb` 可查 | 查重/撞号检查跳过 |
| 质量门 | G1/G2/G4/G5 就位 | G3 依赖引擎，缺了诚实降级 |

**判读原则**：✗ 出现在 ComfyUI / LLM / 引擎三项是**正常的 warn 级降级**，
程序照常工作；只有 L0/L1 项红叉才影响主流程。

### 2.4 启动

```powershell
python -m cardforge launch              # 一键：自检 → 起服务 → 开浏览器（带进度条）
python -m cardforge serve               # 只起服务
python -m cardforge launch --port 8888 --no-browser --skip-check
```

- 默认地址 `http://127.0.0.1:8790`；端口被占自动顺延（+1…+9）；
  已在跑的实例会被**直接复用**并打开浏览器。
- 进度条开关：`CARDFORGE_NO_PROGRESS=1` 关闭 / `CARDFORGE_PROGRESS=1` 强制开。
- ⚠ `启动.bat` 必须保持**纯 ASCII + CRLF**，不要往里加中文——cmd 按 GBK 逐行
  解码会把下一行命令吞掉（缺陷 #31 的教训）。中文提示全部由 Python 打印。

### 2.5 环境变量（可选）

| 变量 | 作用 |
|---|---|
| `CARDFORGE_WORKSPACE` | 覆盖工作区目录 |
| `CARDFORGE_DATA` | 覆盖内置数据目录 |
| `CARDFORGE_VENDOR` | 覆盖 vendor（引擎/脚本库/卡池）目录 |
| `CARDFORGE_OCGCORE` | 直接指定 ocgcore 原生库路径 |

```
┌ 顶栏 ──────────────────────────────────────────────────────────────┐
│ 卡锻logo │ ①规格 ②卡文·脚本 ③卡图·卡面 ④上桌 │ 质量门G1-G5 │ 能力层级 │

├─────────┬────────────────────────────────┬─────────────────────────┤
│ 左栏     │ 中工作区（当前阶段面板）          │ 右栏：艾莉娅陪伴栏        │
│ 工作区   │  欢迎态 / 阶段1-4               │  立绘+气泡+快捷指令       │
│ + 新卡   │                                │  人格切换 / 完整对话抽屉   │
│ 搜索框   │                                │                         │
│ 卡片列表 │                                │                         │
└─────────┴────────────────────────────────┴─────────────────────────┘
```

- **四阶段导航**：造卡流程就是 1→2→3→4，随时可横向跳。
- **质量门状态条**：G1–G5 五枚徽章，绿=通过、琥珀=警告、红=错误、
  灰=未检查、半灰=降级（skipped 绝不显示成通过）。
- **能力层级**：L0–L3 当前可用性徽章（缺哪层降哪层）。
- **⚙ 模型**：大模型配置面板（配/切/试连，与 CLI 同一份配置）。
- **⌘ 系列**：系列圣经面板（建/管/审，见 §五）。
- **艾莉娅**：陪伴栏常驻右栏，六表情 + 呼吸动效；气泡把质量门结论翻译成人话；
  「完整对话」打开抽屉（历史按人格持久化、每条可复制/重试、忙碌可停止）。
  空工作区的欢迎态有「让艾莉娅带我一圈」按钮——新手建议先点它。
- **未保存守卫**：表单有改动未保存时离开页面会弹原生拦截。

## 四、DIY 单卡全流程（主教程）

下面以造一张「星奏的夜曲」效果怪兽为例，把四个阶段完整走一遍。
每步都给出**界面操作**与**等价 CLI**。

> 工作区里已有一张三门全绿的演示卡 `210000011 星奏的见习指挥`
> （G1 pass、G2 pass、G3 真开了一局 38 回合 pass）。先打开它对照看一遍，
> 再动手造自己的。

### 4.0 建卡

界面：左栏「+ 新卡」。CLI：

```powershell
python -m cardforge card new --name "星奏的夜曲" --frame effect --archetype 星奏
# 卡号自动分配（默认 210000000 起，避开官方池），也可 --id 指定
```

卡号规则：CardForge 默认发 `210000000` 以上的号；官方池最大约 9999 万，
**不会撞号**，导出时还会拿官方池再核一遍。

### 4.1 阶段 1 · 规格

**基本信息**：卡号（只读）、卡名、日文名、英文名、卡种（17 种：通常/效果/
仪式/融合/同步/超量/连接 + 六种灵摆变体 + 魔法/陷阱/衍生物/技能卡）。

**怪兽数值**：属性、种族、等级（超量显示「阶级」、连接显示「连接值」自动）、
攻击力、守备力（连接怪兽无守备）。灵摆卡多出**左右刻度**两个字段。
连接怪兽另有**连接标记**格子（点选箭头方向）。

**魔法/陷阱**：选魔法卡类型（通常/永续/仪式/速攻/装备/场地）或陷阱卡类型
（通常/反击/永续）。

**召唤条件**（融合/同步/超量/连接，以及仪式怪兽）：这里是**素材行的唯一填写处**，
卡文第一段与 Lua 的 `Fusion.AddProcMix*` / `Synchro.AddProcedure` /
`Xyz.AddProcedure` / `Link.AddProcedure` / `Ritual.AddProcGreater` 都由它投影：

- **素材段**：选种类（任意怪兽/字段/卡名/种族/属性/卡种/等级/阶级），填数量；
  勾「N 只以上」就是「1只以上 / 2只以上」。同调固定是「协调段 + 协调以外段」，
  每段在「同调角色」里选协调/协调以外。
- **附加条件（同一段里同时成立）**：官方把「字段＋种族」写在**一段**里 ——
  「包含「六武众」怪兽的战士族怪兽2只」。点「+ 附加条件」再加一条筛选，
  卡文会合成「包含「X」怪兽的战士族怪兽×N」，Lua 合成**一个** AND 过滤函数。
  ⚠ 不要拆成两段：两段是「A ＋ B」两组素材，脚本会要两倍的卡。
- **按卡种填入模板**：按当前卡种和你填的系列生成一套能直接改的素材段；
  会覆盖当前素材，所以先问一次。
- **卡名解析卡号**：填官方完整卡名后点「解析卡号」，从官方池/工作区精确匹配；
  没匹配到会列出相近候选。DIY 卡也可以手填卡号。
- **召唤限制**：按规则召唤 / 只能用本卡种召唤 / 只能用以上素材的本卡种召唤 /
  不能特殊召唤。对应卡文「这张卡不用融合召唤不能特殊召唤」与 Lua
  `EFFECT_SPSUMMON_CONDITION`。
- **素材锁定**：勾「不能作为融合素材/同步素材/超量召唤的素材/连接素材」，
  会同时写卡文与 `EFFECT_CANNOT_BE_*_MATERIAL`。
- **额外召唤方法（接触召唤那类「以下方法」）**：一条 ● 一行。选素材所在区域
  （自己场上/手卡/墓地…）与怎么处理（除外/送去墓地/解放/回到卡组/回到手卡），
  默认「用上记的卡」。填了它，召唤限制会自动改写成
  「这张卡用融合召唤**以及以下方法**才能特殊召唤。」并列出
  「●把自己场上的上记的卡除外的场合可以从额外卡组特殊召唤。」；
  脚本侧生成 `Fusion.AddContactProc(...)`。**目前只有融合卡能自动生成脚本**，
  同调/超量/连接会写卡文并把脚本降级成注释（G1 提醒 `G1_SUMMON_METHOD_NOT_FUSION`）。
  勾「不需要「融合」」在条目前面补官方那句「（不需要「融合」）」。
- 面板底部有**简体中文实时预览**，只显示召唤条件段；完整卡文去阶段 2 点「生成」。

素材信息不完整（卡名没解析卡号、字段没字段码）时，Lua 会写成
`-- [CardForge] …需人工补写`，不会生成「任意怪兽」的假流程。额外卡组素材
必须绑字段/种族/卡名，否则 G1 会拦（`G1_SUMMON_MATERIAL_*`）。

> **想照着做一遍？** 仓库里有一集教学视频生成器：
> `python tools/teach_video.py --card <卡号>` —— 它用无头 Edge 打开本地服务
> 的真实界面（`?card=&stage=&panel=` 深链）逐步截图，卡文/脚本/质量门全部
> 取系统当场产物，最后用 ffmpeg 合成 MP4。示例卡见
> `workspace/cards/圣痕/210000021`（融合素材多条件 + 接触召唤）。

**归属**：所属系列（填了没有圣经的名字会当场黄字提示，可一键创建，见 §五）、
字段码 setcode、风味文本。

**效果编辑器**（核心）：「+ 添加效果」逐个添加结构化效果。每个效果填：

| 字段 | 说明 |
|---|---|
| 效果种类 | 56 种（检索、特召、破坏、抽卡、无效、特殊召唤……） |
| 发动时点 | IGNITION（主要阶段）/ 触发时点 / 永续 / 快速等 |
| 次数限制 | 每回合一次 / 每 Duel 一次 / 无限制（注意 HOPT 规则，见下） |
| 目标 | 从哪去（区域）、到哪去（区域）、筛选（种族/属性/卡名/字段）、数量、属于谁 |
| 代价 | 类型（解放/丢弃/去除素材/支付LP…）、数量 |
| 参数 | 按效果种类不同（如检索的字段名、特召的召唤方式） |
| 原文（可选） | 该效果的手写原文，优先于投影 |

也可以**先手写卡文再反推**：「从卡文推断」按钮用纯规则（不依赖大模型）把
中文卡文反推成结构化效果，再逐条确认。

**卡面实时预览**在右栏实时更新。填完点「保存规格」。

CLI 等价：直接编辑 `workspace/cards/<系列>/<卡号>/spec.json`，或界面保存后
`card lint` 查平衡。

**此时 G1 平衡审计自动跑**（左上门徽章）。常见拦截：

- `G1_HOPT_MISSING`（ERROR）：检索/特召类效果没有任何次数限制——现代卡
  默认要写「每回合1次」；
- `G1_ATK_OVER_HARD` / `G1_L4_NORMAL_ATK` 等：打点超官方惯例阈值；
- `G1_LINK_NO_MARKER`：连接怪兽没画任何箭头；
- `G1_PENDULUM_NO_SCALE`：灵摆卡没填刻度；
- `G1_ARCHETYPE_TAKEN` / `G1_SETCODE_TAKEN`：系列名/字段码与官方卡池撞车。

每条问题都带 `→ 修复提示`，艾莉娅气泡也会把结论翻译成人话。

### 4.2 阶段 2 · 卡文 · 脚本

**左半：PSCT 卡文**

- 语言 chips：10 种语言（简中/繁中/日/英/韩/德/法/意/葡/西）。每种语言独立
  句式模板，**不逐词直译**（日文「発動した時/した場合」的差别中英文无法表达）。
- 「生成」：由结构化效果投影出规范卡文（这是主路径）。
- 「整理为标准文本」（**零 AI，只动文本不动 IR**）：把手写的一段效果文本整理成标准
  PSCT 描述，逐段给出「你的原文 → 整理后 + 为什么」。分两层：
  *表层归一*（段号 `1.`/`（1）` → `①`、全角数字、引号配对、标点角色、重复标点）永远安全；
  *整段重写*只在三段都被内核识别、且过「再反解 IR 等价 + 数值保真 + 卡名保真」三道守卫时才做，
  任何一道不过就退回表层并写明原因（例：「重写会丢掉『检索』这层语义」）。
  召唤手续段与卡名级声明**一字不改**（去规格页改）；术语（如「同步→同调」）**只报不改**，
  因为这些词会出现在卡名里。**「采纳全部」只在三门槛全过时开放**，否则逐段采纳；
  想让整理结果变成脚本，用弹窗里独立的「把整理结果同步进 IR」按钮（会先列出反解结果再确认）。
- 「校验」：对编辑器里的文本跑 PSCT 校验器（**39 条规则**，覆盖官方 PSCT
  全部硬性错误：标点三段式、连接词四象限、HOPT 写法、效果处理位置、
  内置特召来源括号、HERO 字段大小写……）。手写内容同样接受校验。
- 「写回规格」：把校验通过的文本写进卡文（多语言）。
- 「AI 起草」（可选）：给一句概念描述，大模型按 11 条 PSCT 约束一次性提议
  草稿；**问题清单与门结论全部由内核产出**，模型在草稿里的自评一律不采信。
  没配模型时按钮明说并给配置入口。

**右半：Lua 脚本**

- 「生成脚本」：效果 IR → ocgcore Lua（23 个片段覆盖可确定性映射的部分）。
  生成不了的效果会写成 `-- 需人工补写` 注释，**绝不瞎编 API**。
- 「静态检查」：G2 门——语法、UTF-8 无 BOM、`GetID`/`c<id>` 约定、
  Stringid↔texts 同步、**API 白名单**（引用了本机引擎不存在的函数会被点名）。
- 「写入工作区」：把脚本与 Stringid 落到 `workspace/script/`。

CLI 等价：

```powershell
python -m cardforge card text   --card 210000020 --lang zh_cn --lang ja
python -m cardforge card script --card 210000020
python -m cardforge card lint   --card 210000020     # G1
python -m cardforge card verify --card 210000020     # G3（需引擎）
python -m cardforge card seal   --card 210000020     # 脚本+Stringid 入库
```

### 4.3 阶段 3 · 卡图 · 卡面

**左半：卡图生成（本机 ComfyUI）**——顶部绿章显示连接状态。表单字段：

| 字段 | 用法 |
|---|---|
| 提示词模板 | 12 套正统卡图母题（骑士/巨龙/咒术师/天使/恶魔/机械/不死/深海/雷兽/荒野巨兽 + 魔法卡无人场景 + 陷阱卡伏击瞬间），按这张卡的**种族/属性/卡种**排好序；只借结构（单主体、一个视点、一个光源、一处最亮），不替你编设定。套进来后仍可逐字改；表单已有内容时先弹对照，可选「只填空白处」。「存为我的模板」把当前这一版存进 `workspace/art_templates/`，跟着项目走 |
| 主体（画什么） | **中文直接写就行**：选 Krea 2 / Qwen-Image 档案时你的原话**逐字**进提示词（这两个底模的文本编码器是 Qwen 系多语言模型）。只有 animagine / pony / illustrious 这类**英文词表 CLIP** 才必须先翻成英文标签，翻不出来的词界面会红字点名 |
| 风格描述 | 系列出图时保持**逐字不变**（冻结风格前缀=一致性锚点）。这里写了取景（半身/特写/远景）或光照（柔光/晨光/逆光），系统默认的「全身可见」「戏剧性强光」两句会**自动撤掉**，不跟你的话对着写 |
| 背景 | **单张与分层都生效**：单张时作为场景句并入提示词，分层时先出这张**没有人**的环境再单独出主体抠底 |
| 工作流 | 文生图 / 分层出图（`t2i_layers`）/ 风格参考等预设 |
| 主体纯色底 | 分层出图时主体的底色：灰(默认最稳)/白/黑/绿幕/品红——主体是白色就别用白底 |
| 模型档案 | 自动选择会给出理由（读你机器实际有的模型）；**档案决定提示词要不要翻译**，见「本机模型」的口径列 |
| 种子 | `-1`=随机；**批量出图每张必须换 seed**，同 seed 构图雷同 |
| 张数 | 1–8 |
| 附加正向/负向 | 追加到提示词（与主体同一语言口径：双语档案原样送，英文档案先翻译） |
| 增强 | 放大 / 抠底 / 分层（背景+主体两次生成，出框时只有主体越窗） |
| 工具 | 「本机模型」看模型清单；「上传我自己的图」不走 ComfyUI；「导出工作流 JSON」可直接导入 ComfyUI 手动精修（**按界面上填的字段编译**，与「预览工作流」一字不差） |

「预览工作流」= 干跑（dry-run），不出图，弹的是**对账页**：口径徽标

没进提示词的词红字列出、以及「这版提示词是怎么拼出来的」逐条说明——
每次撤词、每次翻译都写得明明白白。「打断」中止任务。

### 4.4 阶段 4 · 上桌

**上桌目标**切换：EDOPro ↔ MDPro3/MDPro4。

**EDOPro（expansions 包）**

1. 范围下拉选「单卡 / 整个系列」→「构建」：产出 `workspace/out/expansions/`
   （cdb + script + pics + strings.conf + README + manifest）；
2. 「自检」跑 **G5**：cdb schema、卡号与官方池冲突、脚本 BOM/编码、
   卡图尺寸 421×614、strings.conf 格式……（问题清单见 §七）；
3. 「安装到 EDOPro」：**先点「预演」**（dry-run，列出将要写的文件），
   再「真安装」。真安装会把被覆盖的同名文件**备份到 `.cardforge_backup/`**，
   可回退。没找到 EDOPro 安装目录时会明说。

CLI：`python -m cardforge export --archetype 星奏 --name 星奏包 --install`

**MDPro3 / MDPro4（.ypk 卡包）**

1. 「重新探测客户端」自动找本机 MDPro3（探到会报卡池/脚本/卡图规模）；
2. 填卡包名/作者/（可选）附带一个已保存卡组作演示卡组 →「生成 .ypk」；
3. 文件出现在 `workspace/out/`，页面给下载链接；
4. 游戏内导入五步（界面右侧就有这份指引）：
   **游戏设置 → 导入导出 → 导入 → 文件类型选「扩展卡文件」→ 选中 .ypk**；
   看到「导入扩展卡文件……成功」；回「游戏设置 → 扩展卡包」确认
   **「启用扩展卡」是开的**；编辑卡组时按**卡号**或 **Custom 筛选**找到你的卡。
5. 卡号撞车检查：生成时拿客户端官方卡池逐项核对，撞了直接 ERROR 点名哪张。

**为什么界面不直接写进 MDPro3 目录**：它的脚本在 `Data/script.zip`、卡池在
`Data/locales/*/cards.cdb`，这两处都会被游戏里的「更新先行卡」**整体覆盖**，
写进去等于放在会被冲掉的路径上，且改官方卡池不可逆。`.ypk` 是客户端自己的
正路：一次点击导入，「清空扩展卡」整体回退。

CLI：

```powershell
python -m cardforge mdpro3 --detect                       # 探测本机客户端
python -m cardforge mdpro3 --archetype 星奏 --name 星奏包 --deck 我的卡组 --out workspace/out/星奏包.ypk
python -m cardforge mdpro3 --verify 星奏包.ypk --deep-check # 拆包自检（与客户端逐项对账）
```

**卡组（.ydk）**：`workspace/decks/` 放 .ydk 文件；导出包与 .ypk 都能附带
卡组作为演示卡组。

## 五、系列（系列圣经）全流程

### 5.1 为什么需要系列圣经

G4 系列一致性门审的是「一个系列作为整体成不成立」——没有圣经就没有审计对象，
此时报「通过」才是谎报。所以：**先建圣经，再往系列里造卡**。

### 5.2 创建与管理

界面：顶栏「⌘ 系列」→「+ 新建系列」，填：系列名、setcode、概念、
制胜手段（战斗/效果/烧血/混合）、王牌召唤法（通常/融合/同步/超量/连接/仪式）、
强度定位（休闲/娱乐竞技竞技）。

CLI：

```powershell
python -m cardforge archetype new --name 星奏 --setcode 0x1000 --concept "音律与星辰的演奏者，以奏鸣构筑场面"
python -m cardforge archetype list / show --name 星奏 / check --name 星奏   # check = 跑 G4
```

**实时校验**：规格页「所属系列」填的名字有没有圣经，当场给结论——
没有：黄字 +「现在创建」行内按钮；有：绿字「已有系列圣经，G4 可审计」。

### 5.3 卡表蓝图与 G4 审计

系列圣经内置**卡表蓝图**（五类配额）：

| 角色 | 配额 | 说明 |
|---|---|---|
| 初动点 | 2 | 谁先动、怎么动 |
| 展开点 | 2 | 从初动铺到场面 |
| 王牌终端 | 2 | 场面最终收在哪 |
| 支援 | 4 | 检索/保护/续航 |
| 回收 | 2 | 资源循环 |

「G4 审计」按钮（或 `archetype check`）产出真实建设进度，常见结论：

- `G4_ROSTER_INCOMPLETE`（WARN）：卡表仍有空缺：初动点 0/2、展开点 0/2……
  → **照着缺口造卡**就是系列开发路线；
- `G4_STARTER_TIGHT`：从零启动路径太少，系列启动偏紧；
- `G4_ATTR_SCATTER` / `G4_RACE_SCATTER`：系列属性/种族过于发散，缺乏辨识度；
- `G4_BINDING_BROKEN`：卡的字段/文本声称属于系列，但字段码或名字对不上；
- `G4_GENERIC_EXTRA`：额外卡组的卡没有系列素材要求（泛用素材=不算本家）。

### 5.4 系列出图一致性

没有 ControlNet/IPAdapter 模型时，系列一致性走「**冻结风格前缀 + 每张换 seed**」
（按调研约占一致性效果 60%）：风格描述字段全系列逐字不变，主体各自写，
seed 每张都换。有 clip_vision/controlnet 模型时界面自动启用更强链路。

### 5.5 系列整体导出

`export --archetype 星奏` / `mdpro3 --archetype 星奏` 一次打包整个系列。

### 5.6 示例：把「星奏」系列补满

当前工作区「星奏」有 2 张卡，G4 报缺口：初动 0/2、展开 0/2、终端 0/2、
支援 0/4、回收 0/2。开发路线：

1. 造 1 张 1 星初动（召唤成功检索本家）→ 填初动点；
2. 造 1 张同步/连接展开点（从初动特殊召唤，铺场）；
3. 造 1 张终端王牌（按圣经的 trump 召唤法，带终端效果）；
4. 补 1–2 张本家魔陷（支援/回收）；
5. 每张造完跑 G1–G3，回头重跑 G4 看缺口收窄。

## 六、功能详解

### 6.1 CLI 命令总表

所有子命令都支持 `--json`（机器可读）与 `--quiet`。

| 命令 | 作用 |
|---|---|
| `doctor` | 环境自检（`--json`） |
| `launch` | 一键启动：自检+起服务+开浏览器（`--port --no-browser --skip-check`） |
| `serve` | 只起服务 |
| `render` | 渲染卡面（`--card/--archetype/--demo --rarity --fullart --lang --size --set-number --art --bezel --format`） |
| `card new/lint/text/script/verify/seal` | 建卡 / G1 / 生成卡文 / 生成脚本 / G3 实跑 / 脚本入库 |
| `archetype new/list/show/check` | 系列圣经 CRUD + G4 |
| `export` | EDOPro 包（`--archetype --name --lang --out --install`） |
| `mdpro3` | .ypk 包（`--card/--archetype --deck --detect --verify --deep-check`） |
| `ask` | 问艾莉娅（`--persona professional/lightnovel/tsundere`） |
| `draft` | AI 起草卡文（需先配 LLM；`--card --write --no-g1`） |
| `llm` | 大模型配置（见 §6.4） |

### 6.2 助手「星奏·艾莉娅」

- **陪伴栏**（右栏常驻）：六表情 + 呼吸动效；气泡把质量门结论、任务进度
  翻译成人话（三档语气，**数字与规则号逐字一致**）。
- **抽屉完整对话**：历史按人格分开持久化（刷新不丢、切换只换册子）；
  每条回答带复制/重试；忙碌可停止（Esc）；答不上来给可点的出口建议；
  选中卡后「这张卡」问的就是那张卡。
- **三档人格**：专业 / 轻小说 / 毒舌——语气不同但**规则号与计数逐字一致**
  （自测不变式）。
- **红线**：她的 26 个工具全部转调确定性内核，**零裁决权**；
  「判断归铁律，修辞归我」。无 LLM 时功能不缺失（规则通路）。

### 6.3 官方卡池与查重

内置官方中文卡池 `cards_zh.cdb`（11MB，只读，**永不改动**）。用途：

- 卡名/字段名撞车检查（`G1_ARCHETYPE_TAKEN`、`G1_SETCODE_TAKEN`）；
- 卡号分配与**导出撞号检查**（`G5_ID_CONFLICT`）；
- 术语与句式来源（多语言术语表 213 条 × 10 语言）。

### 6.4 接入大模型（可选）

```powershell
python -m cardforge llm preset lmstudio        # 一键接本机 LM Studio（1234）
python -m cardforge llm preset ollama          # 一键接本机 Ollama（11434）
python -m cardforge llm preset deepseek        # 云端预设：deepseek/kimi/zhipu/qwen/openai/vllm
python -m cardforge llm set --name mycloud --base-url https://api.example.com/v1 --key sk-... --model <名> --use
python -m cardforge llm list / use <名> / off / rm <名> / models / test
```

- 界面顶栏「⚙ 模型」做同样的事；顶栏 chip 显示当前模型。
- 配置落在 `workspace/config/llm.json`（**含密钥，不要提交进 git**）。
- `llm test` 真发一次请求验证连通与模型可用。
- **没配大模型时**：「AI 起草」与 `cardforge draft` 返回 `degraded`，
  明说「规则通路不做自由起草，不拿模板文本冒充 AI 产物」，并给配置入口；
  规则通路（聊天/校验/生成）不受任何影响。

### 6.5 AI 起草卡文

```powershell
python -m cardforge draft "翻转后堆墓的通常陷阱" --lang zh_cn
python -m cardforge draft "……" --card 210000020 --write   # 草稿写回该卡卡文
```

链路：概念（+可选当前卡规格作事实底座）→ 11 条 PSCT 约束提示词 → LLM 一次性
起草 → **内核 lint（39 条）+ G1 出问题清单与门结论**。
红线：草稿里「已符合 PSCT」这类自评**不回传、不影响裁决**；G1 审计的对象是
卡规格而不是草稿文字。

### 6.6 罕贵与出框体系

- 罕贵是「**五层可叠加**」而不是整卡叠一张图：官方罕贵可分别作用于卡名/卡图/
  属性符号/等级星/文本框边框/卡框，所以分区实现；19 种闪膜花纹；
  「不该闪的地方不闪」。
- 出框是「**设计处理**」不是罕贵度（官方名 オーバーフレーム / Extended Art），
  与罕贵正交，可任意叠加（如 OFPSE = 出框+棱镜碎，界面预设里有组合项）。

### 6.7 多语言

10 种语言独立维护句式模板。已知边界（如实）：

- 韩文术语覆盖率 79.3%（44 条缺口集中在动作与 PSCT 句式）；
- 繁中**不用字符转换**生成（`灵摆→靈擺` 会在「钟摆/灵摆」处转错），
  采用台港用词（鐘擺、額外牌組）；
- 日文注音（ruby）未实现——官方日文卡有 4 套注音系统，当前只做正文。

### 6.8 卡图资产与工作流导出

- 「导出工作流 JSON」：把当前出图参数构造成**可直接导入 ComfyUI** 的
  workflow JSON（含使用说明），方便去 ComfyUI 手动精修再回来；
- 「上传我自己的图」：不走 ComfyUI 的通路（L2 缺失时这是主路径）；
- 出图结果落 `workspace/pics/`，卡面合成自动取用。

### 6.9 打包为独立程序

```powershell
# 首次：建构建虚拟环境
py -3 -m venv .packaging\venv
.packaging\venv\Scripts\python.exe -m pip install pyinstaller Pillow numpy fonttools brotli svglib reportlab pymupdf

py -3 tools\build_exe.py                # 约 40s，产出 dist\CardForge\（215.9 MiB）
py -3 tools\build_exe.py --with-engine  # 带上对决引擎（413.5 MiB，仅 Windows 有意义）
py -3 tools\build_exe.py --clean        # 构建前清理旧构建备份（opt-in）
```

- 产物是 **onefolder**：`CardForge.exe` + `_internal/`（Python 运行时+只读资源）
  + **exe 同级 `workspace/`**（可写，用户卡不随临时目录焚毁）。
- **换机器**：拷整个 `CardForge` 文件夹到任意 Windows x64 电脑，双击 exe 即用
  （无参 = launch）。环境检查是**运行时逐项探测**：目标机没有 ComfyUI/引擎/LLM
  就 warn 级降级并明说，核心功能照常。
- 旧构建自动**重命名备份**到 `.packaging/out/prev-*`（自动路径零删除）。
- 未签名 exe 过 SmartScreen：「更多信息 → 仍要运行」；个别杀软对 PyInstaller
  包敏感，加白即可。

## 七、质量门 G1–G5 参考

| 门 | 审什么 | 需要 | 降级行为 |
|---|---|---|---|
| **G1 平衡审计** | 数值阈值（ATK/DEF 按等级惯例）、HOPT 次数限制、连接标记、灵摆刻度、素材具体性、系列/setcode/卡号撞车、卡名长度 | 无 | 不降级 |
| **G2 脚本静态检查** | Lua 语法、UTF-8 无 BOM、GetID/c<id> 约定、Stringid↔texts 同步、**API 白名单**（844 函数/1782 常量，来自本机引擎实测抽取）、SetTarget/SetOperation 配对 | 无 | 不降级 |
| **G3 实跑验证** | 真开一局对战：场景断言（检索进手×2、伤害归属、LP 变动、上界）、脚本真报错才算 ERROR | ocgcore 引擎 | 无引擎 → 静态校验并明说；bot 走不完 → WARN 并写明「内置 bot 局限」，不冤枉你的卡 |
| **G4 系列一致性** | 卡表蓝图缺口、启动路径、属性/种族聚焦、字段绑定、额外卡组本家化、强度定位 | 系列圣经 | 没建圣经 → 报「没有审计对象」并引导创建（绝不报通过） |
| **G5 导出自检** | 构建产物：cdb schema/行数、卡号与官方池冲突、脚本 BOM/编码/空文件、卡图存在与尺寸、strings.conf 格式、manifest | 无 | 缺 Pillow 时卡图尺寸不校验（INFO） |

**判读三态**：pass（绿）/ warn（琥珀，可带豁免留痕）/ error（红，修完再看）。
**skipped（半灰）≠ 通过**——降级与未跑永远如实标注。

G2 的 WARN 级常见项（灵摆/永续魔法/装备魔法/反击陷阱骨架）属于「骨架无片段」
的提示，不是错误；`-- 需人工补写` 的注释就是要你补的地方。

## 八、常见问题与排障

| 症状 | 原因与解法 |
|---|---|
| 双击 `启动.bat` 窗口一闪没反应 | `.bat` 被改出了中文或 LF 换行（cmd 按 GBK 解码会吞命令）。保持**纯 ASCII + CRLF**；中文提示由 `cardforge launch` 打印 |
| 双击打包 exe 一闪而过 | 旧版缺陷 #35（无参被 argparse 打回），当前版本已修（无参 = launch）；确认用的是最新构建 |
| 端口 8790 被占 | 自动顺延 +1…+9；已确认是 CardForge 实例时直接复用并开浏览器 |
| 控制台报 `'gbk' codec can't encode '✓'` | 旧版本问题，已由 `core/console.py` 修掉（自动切 UTF-8 代码页）；升级即可 |
| ComfyUI「未检测到」 | ComfyUI 是否在 `127.0.0.1:8188` 跑着；出图是 L2 可选层，不影响其他功能 |
| 出图物种不对（要独角兽出了龙） | 氛围词把它拉走了。主体字段**直接写英文标签**（`unicorn, single horn, horse body`）；想让属性色温胜出，把属性氛围词放卡种氛围之后 |
| 批量出图构图雷同 | 同 seed 所致——批量每张必须换 seed |
| 找不到对局引擎 | 放 `vendor/engine/ocgcore.dll` 或设 `CARDFORGE_OCGCORE`；装了 EDOPro 会被自动扫到 |
| G3 报 WARN「bot 走不完」 | 这是内置验证 bot 的局限（`blocking: bot`），不是你的卡有问题；引擎真报脚本错才算 ERROR |
| 卡面中文显示方框 | 字体三层策略兜底（OFL→内置→系统 CJK）；doctor 会报告当前字体来源 |
| G4 报「没有可审计的系列」 | 正确防护不是 bug：先用「⌘ 系列」或 `archetype new` 建圣经 |
| 界面下载/图片链接 404 | 确认没有把 `workspace/` 挪走；文件接口只认 WORKSPACE/DATA 白名单内路径 |
| 杀软拦截打包 exe | 未签名 PyInstaller 包常见误报，加白名单 |

## 九、已知限制（诚实清单）

摘自 [03-实现状态.md §五](03-实现状态.md)，选型与商用前必读：

1. 韩文术语覆盖率 79.3%；
2. 繁中采用台港用词，不做字符转换生成；
3. 日文注音（ruby）未实现；
4. 打印拼版（A4 + 裁切线）未实现，只有单卡图；
5. 出框子分类是本项目自定义（官方只有 Extended Art 一个说法）；
6. 对局验证依赖自备 ocgcore；打包版默认不含引擎；
7. 卡框素材与官方字体涉及 Konami 版权——**商用发行前替换 OFL 字体**
   （Cinzel、EB Garamond、思源宋体、霞鹜文楷、Noto Serif KR）；
8. 灵摆版卡框只对存在的实体卡提供；技能卡/暗黑同步用程序化基座；
9. **出图模型许可差异极大**：animagine/qwen_image 可商用；illustrious/noobai
   禁止闭源商业化；**pony 是最大的雷**（限制传递到所有衍生模型）；krea2 商用
   需核对条款——详见 `art/profiles.py` 各档案 notes；
10. Krea2 对具体物种服从度弱，用英文标签控制；
11. 卡种氛围词与属性色温可能打架；
12. 本机无 clip_vision/controlnet 模型时 IPAdapter/ControlNet 链路自动跳过；
13. `.packaging/out/prev-*` 旧构建备份会累积（`--clean` 或手动清）；
14. aria 立绘双镜像（`data/assets/aria/` 与 `web/assets/aria/`），重出：
    `python tools/gen_aria.py --preset all`（需 ComfyUI 在线，seed 20261014）。

### 10.2 卡号与 setcode

- 卡号默认从 `210000000` 起自动分配；官方池最大约 `99995595`，永不撞号；
  导出时还会再核一遍（撞号 ERROR 点名卡）。
- setcode（字段码）建议自定 `0x1000` 起的私有段；与官方撞车会被 G1 拦截。
