### 界面启动即坏的真实原因

`python -m cardforge doctor` 在中文 Windows 上抛  
`'gbk' codec can't encode character '✓'` —— 控制台代码页是 cp936，  
而输出里有 `✓`（GBK 没有这个字形）。**跟功能一点关系都没有，纯粹是控制台不许我们说话。**  
修法是新模块 `core/console.py`：先 `SetConsoleOutputCP(65001)`，再把  
`stdout/stderr` 重配成 UTF-8 + `errors="replace"`（最坏看到一个 `?`，而不是崩溃），  
`stdout is None`（GUI 启动）时换静默写入器。`启动.bat` 同时补了 `PYTHONIOENCODING`。

### L3 驱动的真实 ABI 结论（实测，不是推测）

- 卡组经 `OCG_DuelAddCard` 注入；卡面数据经 **`OCG_DataReader` 回调**按卡号索取  
  （所以 DIY 卡不需要写进 cdb 也能跑）；脚本经 **`OCG_ScriptReader` 回调**按名索取，  
  官方运行库（`constant.lua`/`utility.lua`/`proc_*.lua`）与 `c<code>.lua` 都走这一条。
- 消息帧是 `[uint32 len][uint8 event][紧凑混合宽度 payload]`。
- **响应宽度不能一律按 int32 对齐**：`SELECT_PLACE` 是 int8 三元组、  
  `SELECT_COUNTER` 是 int16 数组 —— 按 int32 写会被核心判定非法。
- `MSG_SELECT_PLACE` 的 `flag` 语义实测&#x4E3A;**「1 = 该位不可用」**：  
  反过来解释时 6/6 局卡死在第一回合，按这个解释 6/6 局打到分出胜负。
- 本 build **只有 `EFFECT_TYPE_QUICK_O` / `EFFECT_TYPE_QUICK_F`，没有 `QUICK_C`**；  
  回卡组是 `Duel.SendtoDeck` 而非 `ReturnToDeck`。凡是凭"通用 ygopro 记忆"写的  
  Lua 都会在这台机器上报错 —— 所以 `data/lua_api.json` 白名单是生成器的硬约束。

## 三-b、MDPro3 / MDPro4 上桌支持

拆了本机客户端目录、扫了 `Assembly-CSharp.dll` 的字符串表、读了  
`Data/locales/zh-CN/translation.conf` 的 UI 键、并**拆了一个社区流通的  
`.ypk`** 逐项对照。

| 事实                                                             | 证据                          |
| -------------------------------------------------------------- | --------------------------- |
| 卡池按语言分在 `Data/locales/<lang>/cards.cdb`，标准 `datas`/`texts` 两张表 | 本机 12 个语言包，zh-CN 有 15019 张卡 |

`** 换行（9113 行含 CRLF） | 直接查库；CardForge 的 `_crlf` 写法是对的 | | 脚本装在 **`Data/script.zip`** 里，内部是 `script/c<卡号>.lua`| 13572 个`c<数字>.lua`+`utility.lua` `procedure.lua`|

新增 `export/mdpro3.py`：`detect()` 自动找到本机客户端（探到  
`D:\MyCardLibrary\mdpro3`，报出卡池/脚本/卡图规模与 `SavedCardSize`）、

界面「上桌」页新增目标切换（EDOPro ↔ MDPro3），带五步导入指引。  
`geometry.OUTPUT_SIZES` 加了 `mdpro3 = (704, 1024)`。

**实测**：4 种卡框（效果 / 超量 / 连接 / 速攻魔法）打成一个包，  
G2 全 pass、cdb 4 行、脚本 4 个、卡图 4 张、演示卡组 1 个、`verify()` 干净，

**真机导入闭环（2026-10-14，用户侧验收）**：用户已在本机 MDPro3 客户端

## 三-e、本轮新增（官方基准深化 + 直接导出卡面 + 卡种显示修复）

三件事：**把 PSCT 校验器补齐到调研报告 §E2 的硬性清单**、**加「直接导出卡面」通路**、  
**修掉卡种下拉显示 `[object Object]`**。

### 1. 卡种显示不正常（缺陷 #32，已修）

界面「卡种」下拉显示成 `[object Object]`。根因：`spec.js` 把  
`Object.entries(meta.frames)` 的 `[key, 对象]` 直接交给了 `select()`，  
而 `select()` 里 `h('option', {value}, zh)` 会走 `textContent = String(对象)`。

**修法（两层）**：

- `ui.js` 新增导出函数 `optionLabel(v, fallback)` —— 从对象里按  
  `zh → zh_cn → label → name → native → en → key` 顺序取可读文本；  
  `select()` 内部统一过一遍，**任何调用点塞对象进来都不会再退化成 `[object Object]`**。
- `spec.js` 的 `frames` 改为显式 `.map(([k, v]) => [k, optionLabel(v, k)])`。

实测：17 种卡种全部输出中文名（通常/效果/仪式/融合/同步/超量/连接/灵摆/…/技能卡），  
`[object Object]` 残留 **0**；界面截图确认真机显示「效果」。

### 2. 直接导出卡面（新通路）

旧路径 `POST /api/render/export` 是**写进工作区 `out/` 并回相对路径** —— 给导出包用，  
用户还得自己去文件夹翻。新增 **`GET /api/render/card-image`**：

| 参数              | 说明                                                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `card` / `spec` | 卡号，或直接 POST 未落盘草稿（与预览同一套 `_spec_view`）                                                                                                    |
| `size`          | `edopro`(421×614) / `mdpro3`(704×1024) / `share`(813×1185) / `print300` / `print`(1394×2031) / `native` / `archive`(2787×4063) / `compat` |
| `sizes`         | 逗号分隔多个 → **打成 zip 一次给**（避免下载一串文件）                                                                                                         |
| `fmt`           | `jpg` / `png` / `webp`                                                                                                                    |
| `scale`         | 放大倍数（自动按基准尺寸等比换算）                                                                                                                         |

- 前端「卡面合成」工具栏加**尺寸下拉 + 格式下拉 + 「直接导出卡面」按钮**，

| 3 | 回答无法复制/重问 | 每条回答裸文本，复制要手动选，重问要重新打字                                   |
| 4 | 没有清空入口    | 想重开一段对话只能刷新页面（配合 2，反而"有用"）                               |
| 5 | 答不上来=死路   | 「不在我的数据源里」之后没有任何下一步建议                                    |
| 6 | 没有忙碌态     | 提问后界面无反馈，慢的时候以为点了没反应                                     |

### 修复（`web/js/assistant.js` 重写 + `api.js` 扩展 + CSS）

- **历史按人格分开持久化**：`localStorage['cardforge.chat.v1']`，结构 `{persona: [msg,…]}`，  
  单人格截断留 80 条。`setPersona()` 不再清空——切换只是**换册子**，同时换内核会话  
  （`store.session=''`，上下文不串）。
- **`say` 家族统一落库**：所有新消息（用户/艾莉娅/已停止）都走 `pushHistory()`，  
  杜绝「界面上有、刷新后没了」。
- **每条回答带操作条**（悬停显示）：复制（`navigator.clipboard` + 1.4s 内「已复制」态）、  
  重试（回溯到最后一条提问，把该问答从记录里去掉后重发——不会出现连续两条一样的问题）。
- **忙碌态 + 可停止**：`setBusy()` 锁输入框、发送键变「停」（Esc 同效）；  
  `AbortController` 取消，`api.js` 的 `send()` **原样 rethrow `AbortError`**  
  （不包成 `ApiError`，调用方要能区分「用户主动停」和「真的失败了」）。  
  `stop()` **立即**把「……」气泡结掉并标记 `is-stopped`，迟到的响应有守卫不覆盖、  
  不重复存历史。
- **答不上来给出口**：命中「不在我的数据源里」类措辞时附四条可点建议。
- **上下文写进 placeholder**：不往对话里插系统消息（那是环境状态不是对话内容，  
  插进去刷新后还会重放）。换卡时经 `cardforge:card-opened` 事件实时更新  
  （该事件此前**只有监听没有派发**，已在 `app.js` 的 `openCard()` 末尾补上）。

| # | 坑                                           | 修法                                                                                |
| - | ------------------------------------------- | ----------------------------------------------------------------------------------- |
| ① | PyInstaller COLLECT **先删输出目录再重建**          | 只写时间戳暂存目录（永不预存在）→ 旧 dist **重命名**备份 → 暂存上位。自动路径**零删除**                        |
| ② | 删除护栏抛 `BaseException` 一族、**直接终止进程**       | 不 catch 它去绕；`--clean` 显式 opt-in 且排在构建**之前**（被拦就诚实失败，不出现"构建成功却非零退出"）        |
| ③ | workspace 骨架放错层（add-data 只能进 `_internal/`） | 构建后 `copy_workspace_skeleton()` 拷到 **exe 同级** `workspace/`；错放则 `/api/cards` 返回空 |
| ④ | PyInstaller 大量 missing warn                | `numpy._core.*` / `fontTools.ttLib.*` 是 `__getattr__` 懒加载被静态追踪的**常规误报**；`win32api` 是标注的可选依赖 |

真机验收（`_probe/accept_pack.sh`，单 shell 调用内起服务→轮询→验→杀）：
frozen 根解析正确（data/web/vendor 均 exists）；13 项检查仅 2 warn

（13 步自检进度条 → 绑 8790 → 开浏览器 → 干净退出）；`--with-engine` 报 L3 `'ocgcore'` 真加载。

### 缺陷 #35：无参双击 exe「窗口一闪、什么都不发生」（latent，打包验收才照出来）

| #  | 缺陷                          | 根因                                              | 修法                                                              |
| -- | --------------------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| 35 | 双击 `CardForge.exe` 一闪而过，无任何输出 | `add_subparsers(required=True)` 让无参运行被 argparse 一句 usage 打回；源码树被 `启动.bat` 显式传 `launch` 掩护，**只有打包态暴露** | `main()` 无参时注入 `["launch"]`（只兜完全无参；显式缺子命令仍给 argparse 的明确报错） |

### 6. 空工作区首次启动验收（`_probe/accept_fresh_ws.sh`）

动机：此前所有打包验收都带着 workspace 骨架跑，「全新机器首次启动」只有
`paths.ensure_dirs()` 的代码声明，没真跑过。脚本把骨架**重命名**挪走（零删除），
起服务验一遍再还原。

结果（全过）：服务 2 次轮询即就绪；`/api/cards` 干净返回 **0 张**；
`archetypes / cards / config / decks / logs / out / pics` 7 个目录惰性建出；
`/` 可达（空工作区欢迎态）；**运行期把光栅化缓存写进可写的 exe 同级 workspace**
（若错写进只读 `_internal` 就会失败）——这是 frozen 缓存路径正确的**正面证据**。

⚠ **验收事故（已修，记入长期记忆）**：上一段的无参 launch 实例**跨会话残留**
（8790 端口，PID 26440，吃 14GB 内存）。它的浏览器页面对着被脚本清空的工作区，
反复重建演示卡/系列——`.history` 快照每几十秒新增一个、骨架 `spec.json` 被改写
成旧内容。症状是「删了又长、还原怎么都对不齐」，文件计数 43→45→47 一直漂。
修法三件：

1. 先 `taskkill` 残留进程（快照立即停止增生）；
2. 脚本加**环境哨兵**：开跑前若发现任何 879x 监听或 CardForge 进程，直接拒绝运行；
3. 还原逻辑改为「运行时现场**整体重命名**留证 + 骨架原位换回」的零删除流程
   （第一版只 `rmdir` 空目录，清不掉运行写出的**文件**，`mv` 回去时把骨架
   挪进了已存在的 `workspace/` 里，还得手动合并）。

终态复核：`dist/CardForge/workspace` **43 文件与源码骨架逐字节一致**；
无 CardForge 进程、无 879x 监听。`--clean` 开关（清理旧现场证据）亦实测通过。

## 三-i、本轮新增（召唤条件：素材行 + 召唤限制）

### 1. 缺陷是什么

旧实现只在 `effects[].params['materials']` 里读素材，而且：

* **卡文完全没有素材行**——融合/同步/超量/连接怪兽的文本框直接以 ① 开头，
  仪式怪兽也没有「「XX」降临」第一行；
* 素材缺失时，**同步/超量/连接照样生成「任意怪兽」的召唤流程**
  （`Synchro.AddProcedure(c,nil,1,99)` / `Xyz.AddProcedure(c,nil,4,2)` /
  `Link.AddProcedure(c,nil,1,rating)`），卡文说一套、脚本做一套；
* 「不能特殊召唤」「只能用融合召唤」「不能作为融合素材」等召唤限制
  既没有结构化字段，也没有 Lua 效果。

### 2. 数据模型（schema v3）

`CardSpec.summon` 是召唤条件的唯一真相源：

| 类型 | 字段 |
|---|---|
| `SummonSpec` | `materials` / `limit` / `cannot_normal_summon` / `cannot_be_material` / `ritual_spell` / `ritual_spell_archetype` / `text_i18n` |
| `MaterialPart` | `kind`（任意/字段/卡名/种族/属性/卡种/等级/阶级）、`value`、`count`、`count_max`、`code`、`setcode`、`tuner`、`exclude_token`、`include_link`、`exclude_link` |

* **旧卡不丢数据**：`content/summon.normalize()` 会把旧版
  `effects[].params['materials']` 读成 `MaterialPart`（旧版同步的单过滤器
  按「协调段」处理，旧版超量的 `count` 迁移成数量）。
* 空 `SummonSpec` 不落盘；`to_dict()` 只写非空字段。

### 3. 卡文投影（`content/summon.py`）

第一段按官方版式生成，排在 ①②③ 之前：

| 卡种 | 中文示例 |
|---|---|
| 融合 | `「青眼白龙」＋龙族怪兽1只以上` |
| 同步 | `龙族协调＋协调以外的「星奏」怪兽2只以上` |
| 超量 | `龙族4星怪兽×2只以上` |
| 连接 | `包含连接怪兽的效果怪兽2只以上` |
| 仪式 | `「星奏的仪式」降临` |

召唤限制行按官方顺序接在后面：不能通常召唤 → 不能作为…素材 → 只能用…召唤。
「用以上记的卡为融合素材的融合召唤才能特殊召唤」会自动接在素材行后。
日文/英文同样有原生模板（如 `1 Tuner + 2+ non-Tuner "星奏" monsters`、
`Must be Fusion Summoned with the above Fusion Materials...`）。

### 4. Lua 投影（`content/lua/fragments.summon_procedure_lines`）

| 卡种 | 生成 |
|---|---|
| 融合 | `Fusion.AddProcMix`（固定数量）/ `Fusion.AddProcMixRep`（单段区间）/ `Fusion.AddProcMixRepUnfix`（多段区间）；具名素材用 `c:IsCode`，字段用 `c:IsSetCard` |
| 同步 | 新版签名 `Synchro.AddProcedure(c,f1,min1,max1,Synchro.NonTuner(f2),min2,max2)` |
| 超量 | `Xyz.AddProcedure(c,filter,rank,min,...,Xyz.InfiniteMats)`；阶级素材走 `c:IsRank` + `lv=nil` |
| 连接 | `Link.AddProcedure(c,filter,min,max,specialchk)`；「包含连接怪兽」生成 `sg:IsExists(Card.IsType,1,nil,TYPE_LINK)` |
| 仪式 | `Ritual.AddProcGreater(c,aux.TRUE,lv)`（desc 不传，避免 `SetDescription(0)`） |
| 限制 | `EFFECT_SPSUMMON_CONDITION` + `aux.fuslimit/synlimit/xyzlimit/lnklimit/ritlimit`；素材锁定生成 `EFFECT_CANNOT_BE_*_MATERIAL` |

**信息不足时宁缺毋滥**：卡号/字段码缺失、超量/连接写了多段筛选条件时，
不生成 `AddProc*`，写 `-- [CardForge] …需人工补写` 并进脚本头注释，
绝不放行「任意怪兽」。

### 5. 前端与接口

- 规格页新增「召唤条件」面板：素材段编辑器、按卡种模板、卡名「解析卡号」
  （`GET /api/pool/name`，官方池精确同名 → 工作区 → 相近候选）、
  召唤限制、素材锁定、简体中文实时预览（`POST /api/psct/summon`）。
- 切换卡种时若原素材段不适配新卡种（如同调需要两段），用应用内对话框
  询问是否换成模板；不覆盖用户数据的选项永远在。
- `/api/meta` 增加 `summon` 词表（素材种类/同调角色/限制/素材锁定/卡种）。

### 6. 质量门

- G1 新增：素材缺失、卡号未解析、字段码缺失、素材数量上下限、同调角色、
  连接素材数量 vs 连接值、超量/连接多段、四类素材锁定冲突、
  额外卡组「不能特殊召唤」矛盾、仪式魔法缺失。
- PSCT 新增 `PSCT_SUMMON_LINE_MISSING`：额外卡组/仪式卡文第一段必须是
  素材行/降临行。
- 顺手修了三个被这次功能照出来的旧缺陷：
  1. `_next_id()` 只问官方池、不看工作区 → 新建卡会拿到已用的 210000000

  2. 额外卡组被误判成「可通常召唤的 3 星效果怪兽」（`G1_L4_EFFECT_ATK`
     误报）；现在额外卡组跳过通常召唤惯例；
  3. `PSCT_BUILTIN_SS_NO_ORIGIN` 把「这张卡不能特殊召唤。」「……才能特殊
     召唤。」当成内置特召；现在只匹配主动写法「可以特殊召唤。」。

### 7. 自测

`smoke 17/17` · `selfcheck_lua 243 PASS/0 FAIL（WARN 11）` ·
`selfcheck_assistant 81/81` · `e2e 26/26`。新增断言覆盖：三语素材行、

### 8. 仍未覆盖（诚实清单）

- **特殊素材约束**：「属性不同」「卡名不同」「相同种族而属性不同」等

- **素材名翻译**：素材卡名/字段名的日英译名需要 `name_i18n`；缺失时回落
  中文原名并在 meta.notes 提示（与效果文本的既有策略一致）。

## 三-j、本轮新增（一段素材叠多个筛选 + 接触召唤）

触发这一轮的是同一张 DIY 卡：
**圣痕龙骑士 露米艾尔**（光／战士族／融合／8 星／3000·2500），
素材「卡名带有「圣痕」的战士族怪兽×3」，并且
「这张卡用融合召唤**以及以下方法**才能特殊召唤。
●把自己场上的上记的卡除外的场合可以从额外卡组特殊召唤。」
（接触融合）。§三-i 落地时这两条都在"仍未覆盖"清单里 —— 这一轮把它们做掉。

### 1. 一段素材可以叠多个筛选（`MaterialPart.also`）

官方把「字段＋种族」写在**同一段**里：实测简中卡池
「包含「六武众」怪兽的战士族怪兽2只」（六武众的军大将）、
「包含「电子龙」的机械族怪兽2只」（电子龙·凯旋）、
「包含魔法师族·4星怪兽的怪兽2只」（圣月之魔导士 恩底弥翁）。
旧模型一段只能有一个 `kind`，于是这张卡被写成两段各 3 只 ——
卡文变成「「圣痕」怪兽×3＋战士族怪兽×3」，脚本要 **6 张**卡。

- `MaterialPart.conditions()` 返回主条件 + 全部附加条件；
- 三语按官方语序合成：zh「包含「X」怪兽的战士族怪兽×3」、
  ja「「X」モンスターを含む戦士族モンスター×３」、
  en「3 Warrior monsters including a "X" monster」；
- Lua 侧 `s.mat{槽}_{段}` 变成**一个** AND 谓词
  （`c:IsSetCard(0x1000) and c:IsRace(RACE_WARRIOR)`），
  `Fusion.AddProcMix` 重复它 3 次，数量不再翻倍；
- 种族常量修正：`_race_lua` 以前反查 `RACE_MAP` 得到的是中文种族名，
  于是永远落到十六进制；现在按位值反查 `RACE_*`，脚本里是 `RACE_WARRIOR`。
- 附带修掉一条官方语序 bug：取对象段区域与数量之间**不加「的」**
  （实测「以自己场上1只」761 例、「以自己场上的1只」0 例），
  中文代价改用官方的「从卡组把1只…送去墓地」（「把自己卡组的1只」0 例）。

### 2. 额外召唤方法（`SummonSpec.methods` → 接触融合）

- 模型：`SummonMethod(action, zone, use_materials, parts, count, no_spelling,
  trigger, text_i18n)`，动作/区域词表在 `SUMMON_METHOD_ACTIONS` /
  `SUMMON_METHOD_ZONES`，`/api/meta` 直接下发给界面；
- 卡文：有 `methods` 时限制行自动改写成「这张卡用融合召唤**以及以下方法**
  才能特殊召唤。」，后面按官方版式逐行列出「●…」条目
  （`no_spelling` 再补「（不需要「融合」）」）；三语都有；
- 脚本：`Fusion.AddContactProc(c,s.cgrp,s.ctop,nil,nil,SUMMON_TYPE_FUSION)`，
  候选组过滤沿用素材行那段条件 + `IsAbleToRemoveAsCost()` 之类的代价可用性，
  处理函数按动作生成 `Duel.Remove / SendtoGrave / Release / SendtoDeck / SendtoHand`。
  **第 6 个参数必须是 `SUMMON_TYPE_FUSION`** —— 否则卡文允许「融合召唤」，
  脚本却被自己注册的 `aux.fuslimit` 挡住；
- 非融合卡：卡文照生成，脚本降级成注释并由 G1 报
  `G1_SUMMON_METHOD_NOT_FUSION`（不假装能做）。

### 3. 顺带补齐的三个效果表达（这张卡的 ①②③）

| 缺口 | 落地 |
| --- | --- |
| 「以对方场上1张**表侧表示**的卡为对象」 | `EffectTarget.face_up` → 卡文前缀 + 脚本 `c:IsFaceup()` |
| 「那张卡的效果**直到回合结束时无效**」 | 新 kind `negate_card` → `EFFECT_DISABLE` + `EFFECT_DISABLE_EFFECT`，`SetReset(...+RESET_PHASE+PHASE_END)` |

| 「对方**把怪兽的效果**发动时」 | 新时点 `OPPONENT_ACTIVATE_MONSTER` → `re:IsMonsterEffect()`，并按「才能发动」生成可选诱发（原来一律 QUICK_F＝强制发动） |
| 「从自己墓地选1只「卡名」**以外的**…」 | `params['select']` 走官方「选」句式；`SelectMatchingCard` 的排除对象补上 `e:GetHandler()` |
| 「被**战斗·效果**破坏的场合」 | `params['destroyed_by']` + when/if 两档 |

### 4. 验证（不是推理，是跑出来的）

- `tools/smoke.py` 新增 **接触召唤上桌（真 ocgcore）**：DIY 素材卡 ×3 上场，

- `tools/selfcheck_lua.py` 243 → **307** 条断言（多条件三语、AND 谓词不翻倍、
  AddContactProc 参数与候选组、negate_card 注册、表侧/选/以外、G1 新增码）。
- 四套自测：smoke 18/0、selfcheck_lua 307/0、assistant 81/0、e2e 26/26。

### 5. 界面与工程附带修正

## 三-k、本轮修复（把系统自己生成的官方卡文贴回来，会烂掉）

用户在**自己的卡**（210000000）上把上一轮生成的官方卡文贴回文本框并保存，界面出现
一串自相矛盾的东西。逐条查下来，全部是**同一条链**上的缺陷：卡文 → IR 的反解
（`effects.infer_from_text`）远比 IR → 卡文的投影弱，弱到会**篡改**用户的卡。

| 现象（截图里能看到的） | 根因 | 修法 |
| --- | --- | --- |
| 「把自己场上1只**只**战士族怪兽送去墓地」「1只**以外的**战士族怪兽」 | 种族正则 `[一-龥]{1,6}族` 往前吞汉字，把「只战士族／以外的战士族／怪兽的战士族」当成种族名 | 词表改成 `constants.RACE_MAP` 的 25 个官方种族（长词优先），只认合法词；「兽战士族」也不会被「战士族」抢走 |
| 卡文多出一条没人写的 ①（`must_first_ssummon`） | 素材行 + 召唤限制 + 「●」条目被当成一条效果反解 | 新增 `summon.split_leading_block()`：投影出的召唤条件段是**产物**，反解前先摘掉，真相源仍是 `spec.summon` |
| 「以对方**怪兽区域**1张表侧表示的卡」 | 「对方场上」被硬映射成 MZONE | 宾语中心词是「卡」→ FIELD，是「怪兽」→ MZONE |
| 表侧表示 / 「这个效果在对方回合也能发动」 / 「对方把怪兽的效果发动时」 / 「被战斗·效果破坏的场合」 / 「从卡组把…」代价 / 「选…以外的」全丢 | 反解词表没有这些措辞 | 逐一补识别：`face_up`、`params['quick']`+QUICK 时点、`OPPONENT_ACTIVATE_MONSTER`、`params['destroyed_by']`、代价区域、`params['select']`+`exclude_self` |
| 「「圣痕龙骑士…」以外的」丢失 | 卡名差一个「的」就判定不是同一张卡 | `_same_card_name()`：忽略空白与助词「的」后**全等**才算自己（不做子串匹配，避免把别的卡误判成自己） |
| 「这张卡不会被战斗破坏」被读成一条破坏效果 | `_ACTION_PATTERNS` 缺「不会被战斗破坏」 | 补齐三种写法 |
| G2 报 `STRINGID_SYNC`，可 Lua 面板写着「还没有脚本」 | 内核在 GET 请求里**现场投影**脚本给质量门用，投影会顺手分配 Stringid 槽位并写脏真 spec | `_lua_of(pair=)`：投影只在**副本**上做，界面用 `lua_preview` 标记区分「预览」与「已落盘」 |
| 提示里出现字面 `**结果**` | 源码里的 Markdown 强调被当纯文本渲染 | `Issue.__post_init__` 统一收掉星号（五道门都受益），`rules._rule()` 同样处理 |
| 官方卡文被判 `PSCT_RESOLUTION_BEFORE_SEMI` **ERROR** | 「处理动词不能写在发动之前」这条规则没考虑代价与被动触发也写在发动之前 | 检查前先摘掉代价句式（`COST_SHAPE_RE`）与被动触发句式（`CONDITION_SHAPE_RE`）；英文只看冒号之前的条件段 |
| 「●…」条目被要求补冒号（`PSCT_MISSING_COLON`） | 效果外文本被当效果段 | `summon.is_summon_line()` 认出来的段落不再要求冒号 |
| 出图弹「规格还没保存，先保存再出图」然后什么都不做 | 拦截式守卫 | 改为**自动保存后继续出图**，保存失败才停（图会落错卡号） |

**回归锁**：`tools/selfcheck_lua.py` 新增 §6b「官方卡文往返」与 §6c「lint 不能判错
自己的产出」——把这张卡的卡文喂进反解，要求 IR 逐字段正确、再投影回来
**与原文逐行相同**；同时保留一条真误用例（把处理写进条件段）必须仍然报 ERROR。
243 → 335 条断言，四套自测全绿。

## 三-l、本轮修复（生图工作流里的提示词不符合输入的要求）

反馈只有一句「生图时工作流里的提示词不符合我输入的要求」。查下来是**三条独立的链**，
全部由 `tools/selfcheck_prompt.py` 锁住（81 条断言）。

**① 词典吞字（主因）**。中文主体一律过 `zh_to_tags()` 翻成英文标签，
没命中的词**静默丢弃**。实测这张卡的主体
「圣痕龙骑士 露米艾尔，银白长发，红色眼睛，手持骑枪，背后展开光之翼，身穿白银铠甲」
被编译成 `dragon, knight, long hair, red, holding, wielding, jousting lance, behind,
in the background, silver, silvery metal` —— 「圣痕／露米艾尔／眼睛／光之翼／铠甲」
整批消失，同时冒出「red / holding / behind」这种单字碎片噪声。
而这条链的前提（「提示词必须是英文」）**在本机根本不成立**：
自动选中的 krea2 档案用 `qwen3vl_4b_fp8_scaled.safetensors`、qwen_image 用 Qwen 系
文本编码器 —— 它们本身就是多语言 LLM，中文原话直接送效果最好。

修法：`ModelProfile` 新增 **`bilingual_text_encoder`**，把「要不要翻译」这件事
交给**编码器**决定而不是写死：

| 档案 | 编码器 | 口径 | 丢词怎么办 |
| --- | --- | --- | --- |
| krea2 / qwen_image | Qwen-VL 系（多语言） | **原文直送**：主体、风格、背景、附加词逐字进提示词，词典不再插手 | 不可能丢 |
| animagine / pony / illustrious / noobai / sdxl / sd15 | 英文词表 CLIP | 必须翻译 | 翻不出来的进 `untranslated`，界面红字点名并给出两条出路（换档案 / 写英文） |

**② 导出工作流走的是另一条小路**。`/api/art/workflow` 只收 `preset/profile/card`，
不读界面上填的主体/风格 → 「导出工作流 JSON」里的 `CLIPTextEncode` 永远只有卡名，
和「预览工作流」对不上。`character_sheet` 预设更狠：直接把整段正向**替换**成固定版式
指令，用户写的主体整个被扔掉。现在导出走 `_request_from()`（与出图同一份请求），
版式指令改为**追加**、负向取**并集**，并把 `prompt_mode/untranslated/user_input`
随 `info=` 回带给界面。

**③ 默认装饰词反对用户的话**。构图句写死「full body visible, ample empty space」、
光照句写死「dramatic lighting, rim light」、卡种氛围句自带「戏剧性施法强光」。
用户写「半身特写、柔和的晨光」时，这三句等于当面把要求拧回去。
新增 `_user_overrides()`：用户描述里出现取景词或光照词，对应的默认句**当场撤掉**
（cfg≤1 的排除句同步换成不声明构图的精简版）；没写则照旧保留——卡图仍然需要
「单主体居中、不要文字边框」这类约束。唯一不撤的是**分层出图的主体 pass**
（全身 + 留白是抠底与压出窗沿的硬需求，notes 里写明）。

**顺带修掉的两处小失真**：`_SPLIT_RE` 以前把 `-` 也当分隔符，用户写的
`8-bit` 会变成 `8, bit`（docstring 声称不会，实际会）；`series_style_prefix()`
在原文直送时用 `", "` 拼接整句，产出过 `"...artwork., 柔和的晨光"` 这种带「.,」的病句，
改为 `_join_slots()` 按句末标点决定分隔符。

**台账**（每张图事后都能复查）：`meta` 新增 `prompt_mode` / `untranslated` /
`user_input` / `prompt_structure`，导出 JSON 的 `extra.cardforge` 同步带上。

**界面**：「预览工作流」弹窗改成**对账页** —— 口径徽标（原文直送 / 词典翻译）、
「你输入的 → 实际送进模型的」逐字段对照表（不一致标红）、丢词红字警告、
「这版提示词是怎么拼出来的」逐条 notes（每次撤词都列明原因）。

**验证（跑出来的，不是推理）**：
`tools/selfcheck_prompt.py` 81 条断言全绿（含「导出 JSON 的节点文本 == 编译结果」
「character_sheet 不覆盖主体」「翻译档中文绝不漏进 CLIP」）；
本机 ComfyUI 真机出一张验证图（krea2 / 8 步 / cfg 1.0 / 832² / 9.6 秒），
画面**逐条对上**中文要求：银白长直发 ✓ 深红眼睛 ✓ 白银铠甲 ✓ 右手持骑枪 ✓
背后发光白色羽翼 ✓ 半身特写（默认全身句确实撤了）✓ 赛璐璐上色 ✓；
四套自测：smoke 19/0 · selfcheck_lua 335/0 · selfcheck_prompt 81/0 ·
assistant 81/0 · e2e 26/26。

## 三-m、本轮新增（提示词模板 + 零 AI 的卡文整理）

两件独立的补齐，都遵循同一条原则：**用户写进去的话，不许悄悄消失，也不许被悄悄改掉。**

### 1. 提示词模板：12 套正统卡图母题（`cardforge/art/templates.py`）

「主体（画什么）」是个空文本框，对不画画的人最难。模板把官方卡图长期沉淀的类型惯例
做成可选项 —— **只借结构（单主体、一个视点、一个光源、一处最亮），不自创设定**
（不替用户编名字、阵营、世界观）。

| 要点 | 落地 |
| --- | --- |
| 取材 | 持械骑士 / 巨龙 / 咒术师 / 天使 / 恶魔 / 机械巨人 / 不死 / 深海巨兽 / 雷兽 / 荒野巨兽 + **魔法卡无人场景** + **陷阱卡伏击瞬间**，共 12 套，分「怪兽 / 魔陷」两组 |
| 语言 | 每套**同时带中文版与英文版**，哪版进表单由 `profile.bilingual_text_encoder` 决定 —— 与上一轮的「口径跟编码器走」是同一条线 |
| 推荐 | `recommend(spec)` 按卡种 +6 / 属性 +3 / 种族 +5 打分排序；**0 分的模板也仍在表里**（推荐是排序，不是替他删选项） |
| 自存 | 「存为我的模板」把当前表单存进 `workspace/art_templates/`，跟着项目走；内置 12 套不给删 |
| 不覆盖 | 表单已有内容时先弹对照（覆盖并套用 / 只填空白处 / 取消），不静默冲掉用户写的东西 |

踩到并修掉的两个坑：① 中文模板名被 `[^a-z0-9_-]` 白名单压成同一个 key `template`，
第二个模板会**静默覆盖**第一个 —— 改成只清路径/URL 不安全字符、保留中文，
且不同标题自动加序号；② 种族打分用子串匹配，`"战士族" in "兽战士族"` 为真，
把「荒野巨兽」顶到「持械骑士」前面 —— 改精确匹配，并且**魔陷卡不参与种族/属性打分**
（`CardSpec` 的字段默认值是 `战士族 / 暗`，照它打分纯属噪声）。

### 2. 卡文整理：`/api/psct/tidy` + `cardforge/content/psct/tidy.py`

内核一直有两条腿（`infer`：文本→IR；`gen`：IR→标准文本），但它们各自只服务一个按钮：
「从卡文推断」会动效果列表，「生成卡文」会覆盖文本框。中间缺的正是用户最想要的那一步：
**我只想把这段文字弄干净，别碰我的卡。** 现在补上，分两层：

* **L1 表层归一**（纯字符级，永远安全）：段号 `1.` / `（1）` / `[1]` → `①`、
  全角数字 → 半角、弯引号/直引号 → 「」、半角 `: ; .` → 全角标点角色、
  重复标点与句末悬挂逗号合并；
* **L2 结构重写**：只有这一段**被内核完整识别**，且过三道保真守卫才动整段 ——
  ① 重写后再反解回来的 IR 指纹（kind/trigger/limit/cost/target/params）逐字相等；
  ② 数字串多重集合相等；③ 「」里的卡名集合相等。任何一条不过就**退回 L1**
  并把原因写进该段（例：「重写会丢掉『检索』这层语义」）。

另外三条硬规定：召唤手续段（素材行 / 「…才能特殊召唤。」 / 「●…」）一个字都不改，
只说去哪改；卡名级使用次数声明单独剥出来原样保留；**术语只报不改**
（「同步→同调」这类词会出现在卡名里，替换会连名字一起改掉）。

界面（卡文页新增「整理为标准文本」）：逐段左原文右整理后 + 状态徽标 + 为什么，
`safe_to_apply` 三门槛（全识别 + 数值卡名保真 + 校验 ERROR 不增加）全过才允许
「采纳全部」，否则只能逐段切换；「把整理结果同步进 IR」是**独立的显式按钮**，
会先列出反解出的效果清单再确认。

### 3. 顺带修掉的四处「说话不算数」

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 手写 `1.` 被整理成 `1。` | 句号归一跑在段号归一**前面** | 调整顺序：段号先归一，且 `\.` 规则不再吃数字后面的点 |
| 「1.5倍」被当成段号① | 段号正则没排除小数 | 加 `(?!\d)` 与 1–20 范围护栏 |
| `"星尘龙"` 整理成 `「星尘龙「` | 直引号一律映射成开引号 | 改为按出现次序**配对**（`_convert_quotes`） |
| 单张工作流下「背景」字段被丢掉 | 背景只在分层出图的背景 pass 里用 | `build()` 现在把背景折进单张提示词；分层的主体 pass 反而**清空**背景（纯色底才抠得干净） |

### 4. 术语表方向错误（官方卡文库实测纠正）

`FOLK_TERMS` 原先写「同调 → 官方是同步」「调整 → 官方是协调」，**方向反了**：
`vendor/data/cards_zh.cdb`（15019 张官方简中卡文）实测「同调」991 / 「同步」0、
「调整」807 / 「协调」0 —— 同步/协调是**繁中**官方词。后果不只是文档错：
校验器会把用户写对的简中卡文报成「民间误译」，而整理器会把它改成错的。

改成 `FolkTerm` 数据类，带 `langs` 与 `level`：

* 方向纠正为「同步 → 同调」「协调 → 调整」，理由里附上库内计数；
* **裁决只作用于 `zh_cn`**（繁中词表未实测，不再拿简中表去判繁中卡）；
* 「翻转」整词判定会误伤普通用语（官方库里那张「把卡组上下翻转过来」），
  改成只在「这张卡翻转 / 翻转的场合 / 翻转效果」三个上下文里提示；
* 「祭品」降级为 `INFO`（旧卡原文确实这么写，114 张），只建议不算错。

### 5. 投影缺陷三处（整理器的守卫把它们全照出来了）

守卫「重写后必须保真」一上线，三类不合法的官方句式立刻暴露 —— 因为重写会改变
数值/量词，只能拒绝，说明投影本身不对：

| 缺陷 | 官方实测 | 修法 |

| 自指效果写成「**1张卡的**攻击力上升300」 | 「这张卡的攻击力上升」568 张 / 「N张卡的攻击力上升」**0 张** | 反解记 `params['self_obj']`，投影据此出「这张卡／このカード／this card」 |
| 字段 + 怪兽写成「1**张**「圣痕」**卡**」 | 「X」怪兽 3791 / 「X」卡 1184（两种都合法但语义不同） | `card_type` 参与字段短语：monster→「X」怪兽、spell/trap→「X」魔法卡/陷阱卡/魔法·陷阱卡；`_target_phrase` 补传 `params`，同一句里量词不再自相矛盾 |

## 三-n、换一台电脑就起不来（缺陷 #36 的闭环）

### 缺陷 #36：只验证「命令存在」，不验证「命令能跑」

| #  | 缺陷 | 根因 | 修法 |
| -- | ---- | ---- | ---- |
| 36 | 别的电脑双击 `启动.bat`：打印 `CardForge - starting ...` 后立刻出现 `The system cannot execute the specified program.`，随后 `[X]`，Python 一个字都来不及输出 | 旧启动器用 `where py` / `where python` 判断解释器，**只证明名字存在**。没装 Python 的 Windows 上，`%LOCALAPPDATA%\Microsoft\WindowsApps\python.exe`（应用执行别名）仍会被 `where` 命中；它是空壳，创建进程直接失败，脚本却拿它去 `-m cardforge` | 每个候选都**真正执行**一次 `version_info >= (3,10)` 探针，失败就跳过：`py -3.13…3.10` → PATH → `.venv` → python.org / conda / uv / scoop / 常见目录 → Store 别名兜底。全部失败时区分「没装 / 太旧 / 装了但启动不了」并调起安装助手 |

配套改动：

- `tools/install_python.ps1`：双语安装助手。优先国内镜像
  （npmmirror → 华为云 → 阿里云 → python.org），下载后校验**官方 MD5**
  与 **Authenticode 签名（Python Software Foundation）**，再
  `/quiet InstallAllUsers=0` 用户级安装（不需要管理员），装完复验并让启动器
  继续；`winget` 只作最后兜底。`-DryRun` 只打印计划。
- `启动.bat` 仍保持**纯 ASCII + CRLF**，并支持 `CARDFORGE_PYTHON` 强制指定、
  `.venv` 优先；错误诊断用英文（英文系统也能读），中文由
  `tools/install_python.ps1` 与 `cardforge launch` 输出。
- `start.sh` 同一套「试跑再采用」规则，并补上 `.venv`、Homebrew/pyenv/conda 路径。
- `cardforge launch` 首次运行缺 Pillow 时征得同意后安装（默认源 → 清华镜像 →
  `--user`），`CARDFORGE_NO_PIP=1` 关闭；非交互 / `--json` 只打印手动命令。

验收（本机复现的四组；静默安装实测到临时目录后已卸载，没有改动现有的 3.13 环境）：

| 场景 | 构造 | 结果 |
| ---- | ---- | ---- |
| PATH 里只有坏 `python.exe` | 0 字节 exe，`PATH=<fake>;C:\Windows\System32` | 跳过坏 exe，自动找到 `%LOCALAPPDATA%\Programs\Python\Python313\python.exe`，`--version` 正常 |
| 完全没有可用 Python | 同上，并把 LOCALAPPDATA / APPDATA / USERPROFILE / ProgramFiles 指向空目录 | 打出「A Python was found, but Windows could not start it.」+ 手动兜底，随后进入安装助手（`-DryRun` 走通菜单与计划） |
| 安装包完整性 | 从 npmmirror 实下 `python-3.12.10-amd64.exe`（26,964,224 B） | MD5 `5eddb0b6f12c852725de071ae681dde4` 与官方一致；Authenticode `Valid`、签名者 `CN=Python Software Foundation`；追加 1 字节后助手判定校验失败并弃用该文件 |
| 缺 Pillow | 干净 venv（无 Pillow） | `launch` 提示 → 同意 → 装好 Pillow 13.0.0 并继续；拒绝则如实降级并给出 `pip install Pillow` |
| 静默安装参数 | 官方安装包 + `TargetDir=%TEMP%\cf-py312-test PrependPath=0 Include_launcher=0` | 9 秒装完，`python.exe` 报 **3.12.10**、pip 25.0.1 可用；随后 `/uninstall /quiet` 清理，目录与 HKCU 卸载项均消失，用户 PATH 无残留 |

> 教训：**「存在」不等于「可用」**。跨机器适配的第一原则是实际执行一次再下结论；
> 只看 `where` / `which` 会把系统留下的空壳当成工具（#31 的「cmd 解码吞命令」、
> #35 的「开发入口掩护打包入口」同属一类）。

## 五、已知限制（诚实清单）

1. **`ko`（韩文）术语覆盖率 79.3%**，44 条缺口集中在动作与 PSCT 句式 —— Yugipedia 对规则类页面普遍不填韩文名。补全需另采韩国官方数据库。
2. **英文的「攻守变化」句式仍是坏的**：`gain_atk` 一类模板是 `{obj} gains {n} ATK`，
   套进英文发动框架就得到 `You can this card gains 300 ATK.`（动词该用原形，
   且官方英文这类句子常不带主语）。这是**本轮之前就存在**的缺陷，
   被整理器的保真守卫照了出来（它拒绝重写，所以没有变得更坏）。
   要修得靠一份英文官方卡文语料定「You can + 原形」的动词表，不能凭猜改。
3. **繁中（`zh_tw`）不做术语裁决**：`FOLK_TERMS` 现在只判 `zh_cn`。
   「同步／协调」在繁中是官方写法、在简中是异体/民间写法，方向相反，
   而手上没有可实测的繁中卡文库 —— 宁可**不判**，也不拿简中的表去套繁中卡。
4. **「整理为标准文本」的整段重写是保守的**：只有该段被内核完整识别，
   且「再反解 IR 等价 + 数值保真 + 卡名保真」三道守卫全过，才动整段。
   手写句子越不标准，越只会得到表层归一（原因逐段写明）。
   要拿到完全标准的卡文，主路径仍是「规格页填效果 → 生成」。
5. **繁体中文不要用字符转换生成**：`灵摆 → 靈擺` 会在「钟摆 vs 灵摆」处转错；本项目的 `zh_tw` 采用台港用词（`鐘擺`、`額外牌組`）。
6. **日文卡面的注音（ruby）未实现**。官方日文卡有 4 套注音系统，是日文 DIY 最大的工程量，当前只做正文不做注音。
7. **打印拼版（A4 拼版 + 裁切线）未实现**。目前可导出 300dpi(697×1016) 与 600dpi(1394×2031) 单卡图。
8. **出框档位分类是本项目自定义的**。官方只有"オーバーフレーム / Extended Art"一个说法，**没有子分类体系**；UI 中已标注为"非官方分类"。
9. **对局验证依赖用户自备 ocgcore**。Windows 用 `ocgcore.dll`、Linux 用 `libocgcore.so`、macOS 用 `libocgcore.dylib`；未检测到即降级为静态校验。**打包版默认不含引擎**（`py tools/build_exe.py --with-engine` 才打入，体积 215.9M → 413.5M）；未带时 L3 静态校验并明说「检查了 64 个候选位置均未找到」，不假装通过。
10. **卡框素材与官方字体涉及 Konami 版权**。`data/assets/` 来自 MIT 仓库，但卡框设计本身是 Konami 的美术；商用发行前请自行评估，并把字体替换为 OFL 字体。
11. **罕见卡种缺素材**：`link`/`spell`/`trap`/`token` 没有灵摆版卡框（官方也没有对应实体卡）；技能卡与暗黑同步无官方框素材，暂用程序化基座。
12. **出图模型的授权差异极大，选型前必看**（已写进 `art/profiles.py` 各档案的 `notes`）：
   | 模型档案                            | 许可                       | 商用结论                                                  |
   | ------------------------------- | ------------------------ | ----------------------------------------------------- |
   | **animagine**（Animagine XL 4.0） | CreativeML Open RAIL++-M | ✅ **可商用** —— 有商业化可能就优先选它                              |
   | **qwen_image**（Qwen-Image 2.1）  | **Apache-2.0**           | ✅ 可商用（含自托管推理与衍生作品）                                    |
   | sd15 / sdxl（通用）                 | OpenRAIL-M / ++-M        | ✅ 多数可商用，但**每个 finetune 可能自加条款**，需逐个核对                 |
   | illustrious / noobai            | OpenRAIL-M + Fair AI 系   | ❌ 明确禁止闭源专有商业化，finetune **继承**底层限制                     |
   | **pony**                        | 修改版 Fair AI 1.0-SD       | ❌ **最大的雷**：禁止在任何允许变现的平台推理（含付费与加速档），**限制传递到所有衍生/融合模型** |
   | krea2（本机首选）                     | Krea 2 Community License | ⚠️ 自托管/个人/研究清晰；**商用需自行核对最新条款**                        |
13. **Krea 2 对「具体物种」的服从度弱于对「氛围 / 材质 / 构图」的服从度**。实测给中文主体「独角兽」出图仍是龙形态（被卡种氛围词里的 dragon 类词元拉走）。要出非默认物种，应在 `ArtRequest.subject` 里**直接写英文标签**（`unicorn, single horn, horse body`），而不是靠中文词典翻。
14. **卡种氛围词与属性色温可能打架**：`fusion monster → violet aura` 会让一张炎属性卡出现紫色光晕。想让色温胜出就把属性氛围词放在卡种氛围之后。
15. **本机 `models/clip_vision/` 与 `models/controlnet/` 为空** → IPAdapter 与 ControlNet 链路不可用。代码是**先探测再决定**（不可用就抛 `model_missing` + 中文回落建议），系列一致性走「冻结风格前缀 + 每张换 seed」（按调研约占 60% 效果）。
16. **`.packaging/out/prev-*` 旧构建备份会累积**：每次重打包按「零删除」架构备份一份（215.9M / 413.5M）。这是安全取舍——自动路径一次删除都不做；清理走 `py tools/build_exe.py --clean`（opt-in，排在构建之前）或手动删。
17. **aria 立绘双镜像**：`data/assets/aria/` 与 `web/assets/aria/` 各一份（源码树渲染用前者，frozen 时 web 走 `_internal` 只读镜像）。改立绘需同步两边，或重跑 `python tools/gen_aria.py --preset all`（需 ComfyUI 在线；保持 seed 20261014 才能维持现有形象）。
