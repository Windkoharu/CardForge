# CardForge 2.0 · 总体设计

> 跨平台 AI 游戏王 DIY 工坊 —— 把「一句话设想」变成「能上牌桌的卡」
> 设计版本 v2.0 · 本文件是全工程的**架构基线**，所有模块规格、数据契约、接口签名都以本文件为准。

---

## 0. 一句话定义

**CardForge 是一个纯本地、零侵入、跨平台的游戏王 DIY 工坊。** 它把「用户只表达意图」作为唯一交互原则，用**确定性内核**（不是大模型）保证出品的卡面、卡文、脚本、导出包全部合规，用**本地 ComfyUI** 产出卡图与美术素材，用一个二次元助手把机器结论翻译成人话。

它交付的不是"能生成图片的玩具"，而是**一条能落地的生产线**：
```
一句话设想 → 结构化规格 → 平衡审计 → PSCT 卡文 → Lua 脚本 → 卡图 → 卡面合成 → 入库 → 导出到 EDOPro 上桌
```

## 2. 四条不可动摇的设计原则

### 原则一 · 用户只表达意图
用户永远不写 Lua、不写 SQL、不填位掩码、不碰十六进制。所有技术细节由内核推导。
> 例外：**高级模式**允许用户直接编辑任何中间产物（`spec.json` / 卡文 / Lua），内核不覆盖手工修改，只做增量。

### 原则二 · 每一步可中断、可回退、可接管
所有中间产物落盘为**可读 JSON**。`spec.json` 是**全流程唯一真相源**——任何环节出问题都能回到它重跑。每个产物带版本快照（`.history/`），支持回滚。

### 原则三 · 质量门自动执行，绝不静默放行
五道门（G1–G5）全部是**确定性代码**，不依赖任何模型。失败必须显式告警 + 给出降级路径；强制放行需填写理由并留痕。

### 原则四 · 机器结论由角色翻译成人话
G1–G5 的原始输出对创作者不友好，统一由艾莉娅转述、解释、给可执行建议。**她的判断必须来自规则或知识库检索，不能是"她觉得"。**

### 附加原则（v2 新增）· 零构建、零安装、零联网可用
- 后端只用 **Python 标准库** + Pillow（唯一硬依赖），不用 FastAPI/Node/数据库服务。
- 前端**零构建**（原生 ES Modules + CSS），双击即用，不需要 npm。
- 全部功能**离线可用**；联网只用于可选的卡池同步与模型下载。

### 3.2 跨平台四层降级（"各个电脑都能用"的落地方式）

能力按**依赖强度**分层，缺哪层就降级到哪层，**没有任何一层会阻断主流程**：

| 层 | 依赖 | 提供的能力 | 缺失时的降级 |
|---|---|---|---|
| **L0 必需** | Python 3.10+ | 全部数据/文本/Lua/导出/UI/卡池/PSCT 校验 | — |
| **L1 渲染** | Pillow（含于多数 Python 发行版） | 卡面 PNG 合成、罕贵、出框、打印级导出 | 浏览器端 SVG 预览仍可用（矢量卡面），PNG 导出置灰并提示 |
| **L2 出图** | 本地 ComfyUI + 模型 | 卡图生成、系列一致性、界面素材 | 保留「上传自己的图」+「占位图」通路，流程继续 |
| **L3 对局** | ocgcore 原生库 | G3 场景单测 + 整局实跑 | 静态 Lua 校验（语法/API/编码）+ 导出，给出各平台引擎获取指引 |

> **L3 平台矩阵**：Windows `ocgcore.dll`；Linux `libocgcore.so`；macOS `libocgcore.dylib`。
> 探测顺序：环境变量 `CARDFORGE_OCGCORE` → 工程 `vendor/engine/` → 常见 EDOPro 安装路径 → 全盘浅搜索。
> 未探测到即**自动降级**，并在 UI 上明确显示「静态校验模式」，绝不假装跑过对局。

### 3.3 CLI 与 GUI 的关系

**GUI 是壳，CLI 是芯。** GUI 每个按钮背后调用的就是这些子命令；CLI 同时充当自动化接口（批量造卡、CI 校验、被 AI agent 调用）。

| 命令 | 作用 | 对应流程 |
|---|---|---|
| `cardforge doctor` | 环境自检（Python/Pillow/ComfyUI/引擎/卡池/字体/素材） | 全局 |
| `cardforge serve` | 启动 GUI | 全局 |
| `cardforge pool sync` | 卡池状态与（可选）同步 | 全局 |
| `cardforge archetype new/list` | 系列圣经 | 系列 S1 |
| `cardforge card new/draft/lint/text/script/art/seal/verify` | 单卡九步 | 单卡 |
| `cardforge series build/check` | 系列批量与一致性 | 系列 S2–S4 |
| `cardforge deck build/analyze/export` | 卡组求解与导出 | 卡组 D1–D5 |
| `cardforge render` | 卡面渲染（含 --rarity/--lang/--fullart/--batch） | 渲染 |
| `cardforge art run/workflows` | 出图 / 导出 ComfyUI 工作流 | 出图 |
| `cardforge export` | 打包 expansions / 一键安装 | 导出 |
| `cardforge ask "..."` | 无 GUI 地问艾莉娅 | 助手 |

## 4. 九大模块规格

依赖方向**严格单向**：`core ← render/content/art/pool/duel ← pipeline ← server/cli`。
任何下层模块**不得** import 上层；跨层通信一律通过 `core/models.py` 的数据类。

### 4.1 `core/` — 领域内核（零依赖）
- `constants.py`：引擎位定义单一真相源（type/race/attribute/link/setcode），数值对齐 `edo9300/ygopro-core` 的 `OCG_*`。
- `enums.py`：卡种（`FrameType` 15 种）、罕贵（`Rarity` 24 种）、语言（`Lang` 10 种）、属性/种族，**每种都自带多语言标签**。
- `models.py`：`CardSpec` / `EffectSpec` / `Archetype` / `DeckSpec` / `RenderOptions` / `ArtRequest` 全部 `dataclass`，带 `to_dict/from_dict` 与**版本号**（向后兼容迁移）。
- `paths.py`：跨平台路径解析，取代旧工程的 `D:\workbuddy workspace\...` 硬编码。项目根通过 `__file__` 向上探测，workspace 可用环境变量覆盖。

### 4.2 `render/` — 卡面渲染（重做，见 §6）
### 4.3 `content/` — 文本与脚本内核（见 §7）
### 4.4 `art/` — 卡图与 ComfyUI（见 §8）
### 4.5 `assistant/` — 艾莉娅（见 §5）
### 4.6 `pool/` — 卡池
- `cdb.py`：`.cdb`（SQLite）读写，`datas` + `texts` 两表，含多语言列。
- `official.py`：官方池查询——**字段名查重**（防 Cipher Soldier 事件）、**卡号占用检查**、术语/卡文检索。
- `repo.py`：项目仓库 CRUD（cards/archetypes/decks），带 `.history/` 版本快照与回滚。

### 4.7 `duel/` — 对局验证（三层降级）
- `engine.py`：抽象接口 + 探测 + 能力上报。
- `ocgcore.py`：ctypes 绑定，实现 `OCG_CreateDuel / OCG_StartDuel / OCG_DuelProcess / OCG_DuelGetMessage / OCG_DuelSetResponse / OCG_LoadScript` 等标准入口，多平台库名自适应。
- `bot.py`：简易决策器（能选就选、优先发动），足以驱动对局暴露脚本错误。
- `scenario.py`：场景单测 DSL（摆场面 → 发动 → 断言）。

### 4.8 `export/` — 导出
`expansions/` 结构、`strings.conf`、`.ydk`、一键安装到 EDOPro 安装目录或生成可 push 的仓库包。

### 4.9 `pipeline/` — 编排与质量门
`gates.py` 定义 G1–G5；`card.py`/`series.py`/`deck.py` 三条流水线；`job.py` 后台任务与 SSE 进度事件。

## 5. 助手角色：星奏·艾莉娅（Aria）

### 5.1 定位
**她是质量门的翻译层，不是花瓶。** 三件事，且只做三件事：

| 职责 | 做什么 | 不做什么 |
|---|---|---|
| **翻译** | 把 G1–G5 结论转述成人话，指出**具体哪一条**触发，给可执行建议 | 不自己下判断——结论永远是代码给的 |
| **向导** | 告诉你当前在哪一步、下一步做什么、为什么这一步存在 | 不替你决定设计方向 |
| **参谋** | 基于知识库给设计参考（"这个打点配检索在官方池里偏高"） | 不替你做最终创作决策 |

### 5.2 四种工作状态（对应立绘表情）

| 状态 | 触发 | 话术示例 |
|---|---|---|
| 引导 | 进入新步骤、等待输入 | 「先定三个锚点吧——胜利方式、王牌形态、属性绑定。这三样定了，系列骨架就有了。」 |
| 工作 | 程序在跑 | 「正在生成 Lua……已过静态检查，现在跑 10 局实跑验证。」 |
| 报警 | 质量门告警/拦截 | 「G1 拦了一下：效果条数到 3 了。建议砍一条，或者拆成两张卡。」 |
| 通过 | 验证通过、入库 | 「三关全过，零脚本错误。这张卡已经进资产库了。」 |

### 5.3 人格档位（默认专业型，可随时切换）
- **专业型**（默认）：简洁、直接给结论与建议，不多话。
- **轻小说型**：日系轻小说笔法，诙谐吐槽 + 细腻内心独白，会吐槽你的卡太超模。
- **毒舌型**：直白毒舌但可靠，毫不留情指出设计问题。

人格只影响**表达层**（`persona.py` 生成的 system prompt 与话术模板），**绝不影响裁决层**。

### 5.4 LLM 接入（四路 + 一路降级）
统一接口 `providers.chat(messages, tools, stream)`：
| Provider | 接入 | 适用 |
|---|---|---|
| `openai_compat` | 任意 OpenAI 兼容端点（LM Studio / vLLM / OneAPI / DeepSeek / 云端） | 默认推荐，本地优先 |
| `ollama` | `http://127.0.0.1:11434` | 零配置本地 |
| `lmstudio` | `http://127.0.0.1:1234/v1` | 零配置本地 |
| `none` | **无 LLM 降级** | 完全离线：用模板话术 + 规则引擎回答，功能不缺失，只是不"聊天" |

**关键约束**：艾莉娅的结论必须来自**工具调用结果**（确定性内核的输出）。工具集：
`card_get / card_patch / card_audit / psct_lint / psct_gen / lua_gen / lua_lint / art_generate / pool_search / pool_dupcheck / archetype_get / series_plan / deck_analyze / export_pack / help_step`

### 5.5 形象与立绘
由**同一套 ComfyUI 管线**生成（角色一致性用 IPAdapter + 参考图，见 §8.5）：基础立绘 1 张 + 表情差分 6 张（引导/工作/报警/通过/思考/惊讶）+ 界面图标一套。实现为**静态立绘 + CSS 表情淡入淡出 + 呼吸微动效**，不做 Live2D。

## 6. 卡面渲染设计（本项目最核心的重做部分）

### 6.1 三段式管线

```
[1] 基座层   base     官方卡框整图（1394×2031）或程序画框体
[2] 内容层   content  插画（含出框溢出）→ 星级/阶级/属性/箭头/徽记 → 文字 → ATK/DEF
[3] 效果层   finish   罕贵覆膜（分层）→ 激光标 → 20 周年标 → 版权/卡号 → 出血裁剪 → 降采样
```
**只在最后降采样一次**（旧版多次缩放导致发糊，这是必修瑕疵之一）。

### 6.2 出框卡（官方名 **オーバーフレーム / Extended Art**）—— 独立子系统

> **术语纠正（调研结论）**：官方日文名 **オーバーフレーム**，官方英文名 **Extended Art**
> （Konami 商品页用词），官方中文商品名 **「超框卡」**（Konami Asia 商品页）。
> 「出框 / 全画」是**中文社区俗称**；英文社区的 "Full Art" 是**误移植的俚语**，非官方。
> **关键定性：出框是「设计处理」，不是罕贵度**——它与罕贵正交，可以任意叠加
> （社区缩写 **OFPSE** = Over-Frame + Prismatic Secret Rare）。2026-02 OCG 首发，2026-04 TCG 跟进。

因此出框单列模块 `render/fullart.py`，与 `rarities.py` 正交，**可自由组合**。

**官方视觉实现规格（直接照做）**：

| 问题 | 官方做法（以 2026 商品样张为准） |
|---|---|
| 插画溢出到哪里 | **内框整片**：官方商品页原文 "extended art going top-to-bottom and side-to-side"；**最外框保留**，插画止于内框 |
| 卡名 / 卡名条 | **没有卡名条**；卡名直接印在画上，按稀有度箔色（金/银）+ 深色描边保证可读 |
| 属性 / 等级 / 阶级 | 浮在画上（各自有金属/浮雕底），不加实心面板 |
| 文本框 | **半透明面板**，有金边 + 投影；**类型行随面板一起包进来并紧贴正文上方**（深字压在面板内，面板上沿只比类型行高 21px）；**魔法/陷阱**的卡种标签按 OCG 官方位置放在类型行右侧（不是卡名下方，那是 TCG 的做法） |
| 正文排版 | **官方档统一墨色**（不做 PSCT 加粗）；行距 1.16 倍字号、段距 0.12 行（官方 ①②③ 连续排）；悬挂缩进 + 禁则沿用现有引擎 |
| 版权行 | **不覆盖** —— 插画在版权表记处被**截断**（必须给插画打 clip 遮罩） |
| 卡号 / 密码 | 卡号在**面板上沿外侧**（白/金 + 描边）；**密码隐藏**（被画面盖住） |
| 插画来源 | 官方常为**整卡重新构图**而非把方窗图放大（登记为不同插画） |

**档位设计**（本项目的自定分类，UI 中明确标注"非官方分类"）：

| 档位 | 名称 | 视觉 | 实现 |
|---|---|---|---|
| `none` | 标准 | 插画严格限制在卡图窗内 | 矩形粘贴 |
| `overframe` | **官方超框** | **2026 官方形态**：插画铺满内框、外框保留；无名条；面板含类型行；密码隐藏 | 插画 = `frame_inset`，版权上方截断；面板从类型行起，半透明 + 金边/投影；名字走稀有度箔 + 描边 |
| `art_bleed` | **出血出框** | 插画上下溢出卡图窗，压住类型行/文本框边缘 | 插画完整矩形绘制，被后绘制的半透明文本面板覆盖；版权行 clip（DIY） |
| `art_over` | **超框（旧·并入官方）** | 兼容别名：历史卡按官方超框几何渲染 | 2026-10-27 并入官方档；界面不再单列 |
| `full_bleed` | **全画** | 插画铺满**整卡**（含外框），卡框以 55% 透明度叠回 | 类型行/卡号/密码按底图明暗自适应对比（DIY） |
| `pendulum_full` | 灵摆出框 | 灵摆框双区分别溢出 | 灵摆专用几何（DIY） |
| `subject_bleed` | **主体出框** | 背景留在窗内，只有主体压出窗沿 | 单图/分层主体 + 窗内原图对齐（DIY） |

> **参考对照**：Rush Duel 的 `Over Rush Rare`（2022）插画出框但不进文本框；
> `Full Over Rush Rare`（2026-04）插画贯穿文本框且文字数值改白字——本项目的 `full_bleed` 对标后者。

每个档位带独立可调参数（溢出量、面板不透明度、卡名描边强度、渐隐高度、版权区截断），全部暴露在 `RenderOptions.fullart`。
`overframe` 的实测规格与实现值见 [06-官方超框规格](06-官方超框规格.md)。

### 6.3 罕贵注册表（声明式，五层可叠加）

① 框底色层      frame_bg
② 卡图·属性·星级层  artwork / attribute / level

`格子网格 grid / 细斑点 dot / 不规则三角 shatter / 规则正方形 mosaic / 水泡 bubble /
不规则小方 / 星形 star / 波状横线 wave / 斜线网格 diag_grid / 放射棒 radial /
星形缩放 star_scale / 正方形+旭光 rising / 象形文字 hieroglyph / KC 基板 kc_board`

Rarity(key="prismatic_secret", label=("棱镜碎","プリズマティックシークレット","Prismatic Secret"),

### 6.4 多语言排版
- **术语与句式**来自 `data/lexicons/terms.json` 与 `psct_patterns.json`；**不做逐词直译**（调研已证实中日文语义不对齐，例如日文「〜が発動した時」在英中无法表达）。
- 每种语言一套 `TextProfile`：字体栈、字号、行距、断行规则、标点挤压、是否用分号、①②编号格式。
- 断行规则：中文按字断、日文按字断（禁则处理：行首不留 `）」、。：；` 等）、英文按词断、韩文按词断、德法按词断并处理长词连字符。
- 中英混排时按字符类别切换字体与字距（旧版混排效果差）。
- **语言可分别设定**：卡名语言、卡文语言、界面语言三者独立（UI 里可做"日中双语卡"这类 DIY 玩法）。

### 6.5 版面几何
`geometry.py` 存纯数值版面（来源：官方卡框实测 + `alixsep/yugilife` 的几何事实），按 **卡种 × 是否灵摆 × 语言** 三维索引，全部可从 JSON 外置覆盖（便于用户微调）。

## 7. 文本与脚本内核

### 7.1 效果 DSL → PSCT → Lua（IR 三段式）

**调研结论（决定性）**：公开世界**不存在** NL→ocgcore Lua 的可用项目，且 ocgcore Lua API **无公开权威文档**——直接让 LLM 写 Lua 必然幻觉。因此采用三段式 IR：

```
自然语言 / 表单 / 模板
        ↓  (LLM 可选参与，只做意图解析)
[IR] EffectSpec   ← 结构化效果：种类 + 时点 + 目标 + 代价 + 限制 + 参数
        ↓  (确定性：句式模板 × 术语表 × 语言)
PSCT 卡文（zh_cn / zh_tw / ja / en / ...）
        ↓  (确定性：片段模板 × 参数填槽)
ocgcore Lua 脚本
```

- `EffectSpec` 是**唯一真相**，卡文与 Lua 都是它的投影。改卡文会尝试回写 IR，改不动则标记 `dirty` 并强制重生成。
- **效果种类注册表**（`content/effects.py`），对标旧版 7 个片段扩到 **30+**：
  检索 / 抽卡 / 特召(手·卡组·墓·除) / 破坏 / 打点增减 / 回收 / 除外 / 送墓 / 无效 / 取对象 / 攻宣反应 / 战斗破坏触发 / 反转触发 / 墓地起效 / 永续 / 装备 / 场地 / 反击 / 计数器 / 灵摆效果 / 连接素材限制 / 融合·同调·超量素材条件 / 一卡多段
  每个种类声明：**可用的时点集合**、**代价选项**、**必需参数**、**Lua 片段**、**PSCT 句式（多语言）**。

### 7.2 PSCT 确定性校验器（`content/psct/lint.py`）
不是"AI 觉得不规范"，而是**规则表**，输出分三级：`ERROR`（必拦）/ `WARN`（告警可豁免）/ `INFO`。

已确定的规则来源（官方 PSCT Part 1–7 + Yugipedia 汇总 + ocg-rule 中文整理）：
- **标点三段式**：`CONDITIONS ： ACTIVATION ； RESOLUTION`（中文）/ `:` `;`（英文）。**有冒号或分号即入连锁**；两者都没有＝不入连锁、不可被响应（魔陷的"卡的发动"例外，永远入连锁）。
- **修正旧文档的错误**：`。` **不是**效果处理分段符——真正的分段手段是**效果编号 ①②③ + 换行**。
- **连接词四象限**（可编码）：

  | 结算方式 ↓ / 必要条件 → | 都不必须 | 必须 A | 必须 A 和 B |
  |---|---|---|---|
  | 顺序 | `also, after that` | `then` | —（无对应词） |
  | 同时 | `also` | `and if you do` | `and` |

  日文对应：`and`=「し」/`then`=「その後」/`also`=「また」/`and if you do`=「その場合」/`also, after that`=「また、その後」；「さらに」无固定英文对应，需按卡核对。
  **关键**：连接词只决定"结算时做多少"，**不决定"能不能发动"**——校验器不得因为用了 `then` 就放宽发动条件检查。
- **HOPT 三种写法必须区分**：①「1回合1次」(限制该张卡，离场/翻里侧重置) ②「这个卡名的①②效果1回合各能使用1次」(限制玩家+原本卡名；`use` > `activate` > `apply` 严格度递减) ③「(这个效果1回合只能获得1次。)」(跨卡名限制玩家)。
- **中日文不使用分号**——靠语序区分 cost 与效果处理。校验器需按语言切换规则集。
- **取对象判定分期**：第 9 期后「以〜为对象」；第 8 期「选择」(取) vs「选」(不取)；第 8 期前需查裁定，**不做自动判断**，标 INFO 提示人工确认。
- 时点词校验：`时` vs `场合`（英文 `when` vs `if`）；日文「〜が発動した時」= 直接连锁、「〜を発動した場合」= 该效果处理完毕后，中英文无法表达，**多语言生成时标 INFO 提示**。

### 7.3 平衡审计（`content/design.py`）—— G1 的确定性规则
来自官方卡池统计出的"成文惯例"（Yugipedia `Level 4 ATK and DEF conventions` / `Conventions of 3000 ATK and DEF`）：
- 等级 ≤4 且可通常召唤：**ATK > 2000 必须有负面效果**；**ATK = 2000 必须是通常怪兽或带负面效果**；**DEF ≥ 2500 必须有负面效果**。
- 4 星通常怪兽 ATK 上限 **2000**（官方明文表述为 "the maximum possible ATK for a Level 4 Normal Monster"）。
- 通常怪兽 ATK **不应 ≥ 3000**（青眼白龙为天花板）；**ATK/DEF > 3000 必须有负面效果或阻止通常召唤的条件**。
- 效果条数 **≤ 2**（官方建议）；**≥ 3** 标 Post-Modern 设计告警；**≥ 4** 直接拦截。
- 速攻效果只有怪兽卡有（魔法/陷阱没有 2 速）。
- 现代卡默认 HOPT；缺失则**强制补全**。
- 泛用素材雷区：额外卡组素材必须绑字段，**禁止「任意 2 只怪兽」**（Isolde / Baronne / Halqifibrax 的共同死因）。
- 字段名查重：查官方池 FTS 索引，命中即**拦截**（防 Cipher Soldier 事件）。
- setcode / 卡号冲突 → 拦截。
- 红旗清单 22 条（无条件卡组特召、无代价抽卡、可反复利用的墓地资源、无限 loop、FTK、封锁操作、手牌破坏、无视召唤条件、素材过泛、卡组直接送墓……）。

### 7.4 Lua 生成与静态门（G2）
- 片段模板化组装，`aux.Stringid(id, n)` ↔ `cdb.texts.str*` **自动同步**（否则效果描述显示 `???`）。
- G2 检查项：① Lua 语法解析（内置轻量 Lua 词法/语法校验器，无需 `luac`）② **UTF-8 无 BOM**（带 BOM 直接失效，事后不可补救）③ API 存在性（白名单从 `vendor/scripts/constant.lua` + `utility.lua` 抽取，内置快照）④ `Stringid ↔ texts` 同步。
- 输出**人类可读+可编辑**的 Lua，重新生成会覆盖但保留 `.history/`。

## 8. 卡图与 ComfyUI

### 8.1 两个交付物（用户要求 2 的完整回答）
1. **连得上的活管线**：本地 ComfyUI 直接出图，单张 / 批量 / 系列一致性。
2. **拿得走的工作流**：一键导出 `.json`，用户**拖进 ComfyUI 就能跑**（含节点说明与推荐模型/参数注释）——即使不用 CardForge，工作流本身也有价值。

### 8.2 客户端设计
- `client.py`：`GET /system_stats` 探活 → `GET /object_info` 拿**本机真实可用**的 checkpoint / lora / controlnet / upscale 模型清单 → `POST /prompt` 提交 → 轮询 `/history/{id}`（可选 WebSocket 拿更细进度）→ `GET /view` 取图。全程 `urllib`（标准库），无需 requests。
- `probe.py`：**模型自适应**——按优先级探测 `Illustrious / NoobAI / Pony / Animagine / SDXL / SD1.5 / Flux` 系底模与常用 LoRA，自动挑选并给出适配的分辨率与采样参数。用户不需要懂模型。
- 出错分类：离线 / 节点缺失 / 模型缺失 / 显存不足 / 采样超时，各给**可执行的中文提示**。

### 8.3 工作流为「函数式构造器」而非死 JSON
`graph.py` 用代码搭图（节点 id 自动分配、连线自动生成），`presets.py` 提供预设：
`t2i_single`（单卡图）/ `t2i_series`（系列批量，共享风格）/ `style_ref`（风格参考垫图）/ `character_sheet`（角色三视图）/ `ipadapter_consistency`（同角色多图一致）/ `upscale`（放大）/ `remove_bg`（抠底）/ `inpaint_edit`（局部重绘，用于 Qwen-Edit 类模型）。

> 好处：**没有死 JSON 的兼容性问题**。节点 class_type 随 ComfyUI 版本变化时只改构造器；同时 `export_ui.py` 能把构造出的图**回写成 UI 格式**（nodes/links）供用户导入。

### 8.4 一致性方案（系列卡图的关键难点）
三层手段，按可用性自动降级：
1. **风格参考垫图**（`style_ref`）：把用户指定的风格图或已生成的满意卡图作为风格锚点（IPAdapter / 参考图 latent）。
2. **角色一致性**：IPAdapter（`IPAdapterUnifiedLoader` + `IPAdapterAdvanced`）+ ControlNet 控制构图；同角色多图共享参考图与固定 seed 基底。
3. **LoRA 训练通路**（可选）：为系列训练专属 LoRA，接口预留（不内置训练，给出参数与命令）。

### 8.5 提示词工程
`prompt.py` 把用户的中文风格描述（如「赛璐璐平涂、逆光、夕阳下的魔法学院」）结构化为分层提示词：
`画质词 + 主体词 + 卡种氛围词（按 frame 自动加）+ 构图词（卡图窗比例）+ 风格词 + 光照词 + 负向词`。
内置卡图专用负向词（文字、水印、多手、多指、边框、签名）与「无文字」强制约束。

### 8.6 卡图资产库
每次生成保留 `workspace/pics/art/<id>/v{n}.png` + 元数据（提示词、模型、seed、参数、工作流指纹），支持**版本对比与回滚**（旧版只有单一 `history`，不可对比）。

## 9. 调研结论（决定架构的关键事实）

| # | 结论 | 对本设计的影响 |
|---|---|---|
| 1 | 公开世界**不存在**可用的 NL→ocgcore Lua 项目；ocgcore Lua API 无权威公开文档 | 走 **IR 三段式**，模板化生成，不做直译 |

| 4 | 官方从未定义「。」的语义；分段靠①②③编号 | 修正旧文档错误；linter 规则按此实现 |

| 6 | 日文「〜が発動した時」/「〜を発動した場合」的差别在英中**无法表达** | 禁止逐词直译；多语言生成走独立句式模板，并对不可译点标 INFO |

| 8 | 官方简中数据库的检索界面即**官方术语表**（Synchron=同步、Xyz=超量、Tuner=协调…） | 术语表以官方简中为准，不以民间习惯为准 |
| 9 | ATK/DEF 惯例是**官方卡池统计出的成文惯例** | G1 用这些硬阈值，而不是"感觉" |
| 10 | 既有 DIY 工具的通病：只能出图不能出脚本、罕贵不全、出框做不出、不能批量做系列、文本不规范 | 本项目的六项差异化卖点正好对应 |
| 11 | EDOPro 侧可控资产：`ProjectIgnis/CardScripts`（22k 官方脚本 = 卡文↔Lua 配对语料）、`Satellaa/ocgcore`（便于自制卡整合的核心） | 用官方脚本库反向校验 API 白名单与句式 |
| 12 | 卡框素材来源 `kooriookami/yugioh-card`（**MIT**），几何来源 `alixsep/yugilife`（只取数值） | 许可链清晰，可随工程分发；素材署名义务由 `data/assets/NOTICE.txt` 承担 |

## 10.5 素材与字体许可策略（合规红线）

调研确认了两条必须写进设计的法律事实：

1. **官方卡框素材的归属模糊**。所有已知的 PSD/矢量卡框模板（DeviantArt、cardmaker.net 论坛、
   百度贴吧）**都没有明确的开源许可**，且卡框本身是 Konami 的美术设计。**没有任何一份卡框素材是以
   MIT/CC0/CC-BY 发布的**——本项目现用的 `kooriookami/yugioh-card` 是唯一有明确 MIT 声明的来源
   （该仓库为 Canvas 自绘 + 自带资源，MIT 覆盖其分发行为）。
2. **官方字体全部是商业字体**（Matrix / Matrixed / ITC Stone Serif / DF 隷書体 / FOT-Rodin /
   HanWang LiSu / DF Kai W5）。社区流传的"游戏王字体包"属于二次分发，法律风险高。

因此采取**三层素材策略**，让工具在三种情况下都可用：

| 层 | 内容 | 默认 | 适用 |
|---|---|---|---|
| **A 内置素材** | `data/assets/`（MIT 来源的卡框整图 + 字体），随工程分发并附 `NOTICE.txt` 署名 | 开 | 个人 DIY、学习、非商业分享 |
| **B 系统字体回退** | 自动探测系统 CJK 字体（Windows msyh/simhei、macOS PingFang、Linux Noto CJK） | 自动 | A 缺失时保证**一定出得了字**，绝不出现方框 |
| **C OFL 字体方案** | 引导用户安装开源字体：**Cinzel**（≈Matrix Small Caps）、**EB Garamond / Noto Serif**（≈ITC Stone Serif）、**思源宋体 / Noto Serif SC·TC**、**霞鹜文楷 LXGW WenKai**（≈DF Kai）、**Noto Serif KR** | 可选 | **商业发行必须走 C** |

`fonts.py` 的字体栈按 `C → A → B` 顺序解析；`cardforge doctor` 会明确报告当前用的是哪一层，
并在使用 A 层时打印许可提示。**生成的卡面用于商业发行前，必须替换为 C 层字体**——这一提示会
同时出现在文档、`doctor` 输出与导出包的 `README.txt` 里。

## 11. 五道质量门

| 门 | 位置 | 检查项 | 失败处理 |
|---|---|---|---|
| **G1** | 规格生成后 | 平衡三角 / ATK·DEF 惯例 / HOPT 强制 / 效果条数 / 泛用素材 / 字段查重 / setcode 与卡号冲突 | 告警或拦截，回 IR；**可强制放行但留痕** |
| **G2** | 脚本生成后 | Lua 语法 / UTF-8 无 BOM / API 存在性 / `Stringid ↔ texts` 同步 | 回脚本层；或降级重试 |
| **G3** | 落盘后 | G3a 场景单测 + G3b 整局对战 0 报错 | 回脚本层（唯一能发现结算错误的关卡）；**无引擎时降级为静态校验并明确标注** |
| **G4** | 系列批量后 | 方言句式 ≤5 / 属性种族交集 / 从零启动路径 ≥2 / 泛用素材 / 卡表角色覆盖率 | 告警，回系列蓝图 |
| **G5** | 导出打包后 | 文件完整性 / 编码 / 卡号冲突 / cdb 表结构 | **拦截导出**（防止交付坏包） |

## 14. 与旧版（v0.x）的关系

旧工程 `cardforge`（v0.3.0）已验证的资产**全部继承**：
官方卡框素材（MIT）、版面几何、ocgcore 调用经验、CDB 读写、ComfyUI 客户端经验、Lua 片段模板思路、设计方法论知识库、22k 官方脚本库、中文卡池。

**明确重做的部分**（用户指出"合成功能存在瑕疵"）：
| 重做项 | 原因 |
|---|---|
| 罕贵实现（整卡叠图 → 声明式分层） | 不该闪的区域也在闪 |
| 出框/全画（新增子系统） | 旧版不具备 |
| 文字排版引擎（重写） | 断行/混排/字号自适应/①②编号/灵摆排版不稳 |
| 降采样链（多段 → 单次） | 多次缩放导致发糊 |
| 素材与字体装载（重写） | woff2/SVG 依赖链脆弱，缺字体时表现差 |
| 多语言（新增） | 旧版仅中文 |
| 渲染架构（单文件 52KB → 分层 8 文件） | 可维护性 |
| 路径（硬编码 → 解析） | 跨平台 |
| 服务端（`http.server` 手写路由 → 声明式路由表 + SSE） | 可维护性 |
| 对局（无 → 三层降级） | 无引擎也能用 |
